# 도서관리 요구사항 분석 — 자체 판단·가정 대장

2026-10-04. [분석 본문](library-management-analysis.md), [유스케이스](library-management-use-cases.md), [조사 원문·사용자 결정](library-management.md)을 연결한다.

**초기 보수 재분류:** [사용자 직접 확인 대상](library-management-confirmation-required.md)에 최초 구현 분류를 남겼다. 이 대장의 답은 분석용으로 유지하지만 미해소 U 부분은 제품 설계/구현 확정에 사용하지 않는다. AS61개를 U41·조건부 C1·기존 확정4·기술9·가역4·위임 검토2로 전수 분류했다. 가정 밖 보존/시간 누락도 CF에 따로 기록했다.

**최신 후속 분석:** Q26까지 첨부와 이번 잔여 11개 답변으로 기존 행을 교정했다. 출처는 [질문형 목록](library-management-confirmation-questions.md), 영향은 [분석 §12](library-management-analysis.md#implementation-holds)다. AS090~105의 새 판단을 §4에 모았고 고영향 해석은 CF48~55로 구현 적용을 분리했다. 사용자 직접 답변을 받은 규칙은 더 이상 미응답 가정이 아니며, 새 가정은 분석에만 적용한다. 초기 AS61개 분류/과거 교정 사례는 역사적 기록이다.

## 1. 이 대장의 의미

사용자의 지시: “요구사항 분석 중에 생기는 질문은 스스로 해결하되, 스스로 해결한 부분에선 표식을 남기고 별도로 모아둬서 추후 바로잡을 수 있도록 준비 … 당시엔 일단 맞다고 가정하고 진행.”

아래의 모든 `AS-LIBRARY-…`는 **분석에서 채택한 작업 가정**이다. 앞선 분석 위임에서는 사용자에게 질문을 보내거나 답을 기다리지 않고 이 의미를 참으로 두어 후속 분석을 진행했다. 사용자 확정 DEC와 구분하며, 인터뷰 답변·실측·구현 완료로 승격하지 않는다. 기술 지원 여부를 확인하지 못한 것은 TV 항목과 연결한다. 이 대장 자체가 전체 승인 대기 목록은 아니며, 최신 CF 분류에서 일부 해석의 직접 확인/구현 보류와 독립 기술·가역 선택을 구별한다.

- 상태: 활성(분석에 적용) / 수정됨(후속 대체 ID와 새 의미) / 철회(미적용) / 사용자 확인됨(실제 확인 근거 필요).
- 기존 AS 행은 최신 출처로 교정했으며 직접 답변으로 확인된 부분과 남은 보완을 근거 열에서 구별한다. 새 AS090~105는 분석 활성이고, CF48~55에 연결된 부분은 구현 보류다. 영향도만으로 전체 행의 구현 허용을 결정하지 않는다.
- 우선 적용 순서: 새 사용자 지시 → 최신 사용자 DEC → 기존 위임 기본안 → 이 대장의 작업 가정. 충돌을 발견하면 낮은 우선순위 쪽을 갱신한다.
- 같은 가정의 기준은 이 파일이다. UC와 분석의 표식은 사용 위치이며 별도 정책 정본이 아니다.
- AS001~041은 공통 판단, AS070~089는 기존 상세 UC 판단, AS090~105는 후속 응답 분석의 새 판단이다. 사이 번호는 아직 부여하지 않은 예약 범위이며 누락된 결정이 아니다.

### 5.2 교정 작업의 최소 절차

1. 바꿀 AS ID와 새로운 사용자 지시/검증 근거를 지정한다. 해당 가정은 그대로 번호를 유지하며 이전 내용·새 내용·근거·일자를 변경 기록에 남긴다. 사용자 확정 DEC의 의미를 조용히 수정하지 않는다.
2. 이 대장의 답/상태/영향 위치를 먼저 바꾼다. 바뀐 답이 다른 가정과 충돌하면 함께 수정하거나 명시적으로 대체한다.
3. 영향 ID의 SR 결과/사전/상태·결정표/OP 성공·최소 보장과 상세 UC의 Extensions/AC를 같은 의미로 갱신한다.
4. TC의 예상값과 TV의 종료 조건을 새 규칙에서 다시 도출한다. 테스트에 맞춰 정책을 바꾸거나 구현 결과를 예상값으로 복사하지 않는다.
5. 문서 참조/정본/표/경계 산술을 재확인한다. 실제 구현이 생긴 뒤의 변경이면 관련 타입/저장/시각/권한·실패/회귀 검증을 함께 수행한다. 지금은 앱 테스트 결과가 없으므로 기존 통과라고 보존할 항목도 없다.
6. 변경과 수행 검증·미실시·남은 제약을 분석 기준선의 기록에 추가한다. 거짓 사용자 승인/실현 가능성 통과를 붙이지 않는다.

예: AS002를 표시 기한23:59:00 기준으로 교정하면 알림 계산·TC009/AC 알림 기대 시각만 이동한다. 연체 자체는 AS070의 다음날00:00 기준을 유지할 수 있다. AS017을 다른 만료 계약으로 교정하면 쿠키/컨텍스트/TV005만 먼저 변경하고 학번으로 과거 기록을 복구하는 새로운 기능을 자동 추가하지 않는다.
