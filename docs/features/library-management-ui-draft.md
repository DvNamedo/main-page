> **현행 범위:** SD 공통 경계→기존 Figma 표시·배치·접근성 정비→화면별 계약→프론트 껍데기 구현을 수행했다. §1~9의 ‘앱 코드 미구현/후속 OOD’, §10~13의 전부 미실행은 각 작성 당시 기록이다. 최신 후속 회원·관리자 표본 검증은 §14와 케이스 §4를 따른다. 브라우저 30/30·단위 9/9, 타입·린트·빌드가 통과했으며 실제 업무/연동과 전체 접근성 QA는 미완료다.

## 1. 목적·범위·출처

- 최신 요청: 인계 문서와 프로젝트 지침을 읽고 도서관리 Figma UI 초안을 이어가며 테스트 보류 유지.
- [인계 §13~15](library-management-handoff.md#13-ui-초안의-출발점과-미정-범위), [현행 분석](library-management-analysis.md), [가정 대장](library-management-assumptions.md), [상세 UC](library-management-use-cases.md)를 재사용했다. 요구 수집·동일 원인 분석을 처음부터 반복하지 않았다.
- 방문자/회원의 도서 선택·대출·자기 기록·반납·연장·알림, 관리자/마스터의 관리 목표를 화면으로 탐색한다. 사진 사후 검토를 선행 승인으로 바꾸지 않는다.
- Figma에서 편집 가능한 초안을 작성했다. 앱 업무 코드, 내부 모듈·DB·세션·트랜잭션 상세 OOD, 실제 저장/권한/발송/삭제/배포는 이번 범위 밖이다.
- **테스트 보류 유지:** 단위·모델 실행, 앱 실행, 타입 검사, 린트, 빌드, 브라우저 제품 시험, 실제 DB/Drive/메일/Push 호출 미실행. Figma 작성·렌더 이미지 읽기·레이어/문구 대조는 디자인 산출물 검토로만 기록한다.

Planning은 기존 목적·경계·제약과 이번 디자인 인수 기준을 재사용했다. OOA는 기존 UC·규칙을 화면 표현에 연결했다. OOD는 UI 표현의 책임만 탐색하며 내부 구조를 확정하지 않았다. 구현·테스트는 시작하지 않았고, QA는 초안 산출물의 문구/구조/시각 검토에 한정했다.

## 10. 전체 화면 표시·배치·접근성 정비

2026-10-05 · 최신 사용자 요청의 2단계. [SD 공통 경계 SC01~08](library-management-design.md#structural-boundaries)와 §5의 기존 28종 화면·UC·OP를 재사용했다. 사용자가 수정한 **현재 Figma를 먼저 읽은 뒤** 기존 원본·`P/`의 레이어/문구/반응을 보존하며 A03/A05의 선택·상세를 보완하고, 기존 화면에서 넓은/좁은 배치와 상태 표본을 파생했다. 새 업무 규칙·흐름·화면 기능을 추가하지 않았다.

방법 선택: P02의 통합 기능 기록, P07의 미정 의미 분리, D02/D03의 표현·책임 표, D04/D05의 전달 데이터·권한 경계, D11/D12의 기존 컴포넌트·최소 변경, T11/T12의 산출물·추적 정적 대조를 적용한다. T10의 기기·키보드·보조기술 조건은 설계와 후속 케이스에 남기며 실행하지 않는다. 기존 분석 재수집·새 Fully Dressed UC·DFD 재작성·새 프레임워크는 변경한 업무 의미가 없어 생략한다.

### 10.1 Figma 변경과 보존 근거

- [표시·반응형·접근성 보드 `45:1043`](https://www.figma.com/design/Z8KgF0LpnRQaHduUmkn3iR?node-id=45-1043)에 기존 화면에서 파생한 배치와 읽기/선택/포커스 기준을 모았다. 기본 화면은 여전히 M01~08·A01~08·S01~12의 28종이다.
- 넓은 회원 배치 M01~08: `45:1046`, `45:1096`, `45:1137`, `45:1168`, `45:1203`, `45:1228`, `45:1251`, `45:1284`.

- 긴 값 `45:1926`, 빈 목록 `45:1977`, 처리 중 `45:1990`, 부분 결과 `45:2009`는 **표시 표본**이다. 처리·부분 저장을 실제로 수행한 결과가 아니다.
- A03 원본 `7:226`·탐색 `13:1623`에 B-01~03의 단일 선택, 선택 1권과 B-01 편집 대상을 맞췄다. A05 원본 `7:351`·탐색 `13:1747`에 L-01/L-02 선택·선택 2건과 F-01 동결/P-01 제재의 ID·사유 상세를 보완했다. 책/대출/동결/제재를 같은 종류의 대상처럼 세지 않는다.

- 새 식별 텍스트의 높이와 카드 열 라벨/값의 읽기 순서를 렌더 이미지로 대조해 교정했다. A03/A05·좁은 A01/A06/A05·긴 값/부분 결과 표본의 후속 렌더를 읽었다. 이 근거는 해당 디자인 산출물의 표시 확인이며 전체 화면의 실제 기기·제품 실행 검증이 아니다.

### 10.3 읽기·키보드·포커스·상태 기준

다음은 프론트 구현과 미실행 케이스의 판정 기준이다. Figma의 주석/배치가 실제 키보드나 보조기술 동작을 검증했다는 뜻은 아니다.

- 읽기/DOM 순서는 화면 제목→예시/미연동 안내→필터/입력→목록→현재 선택/건수→해당 상세→확인/결과로 맞춘다. CSS로 순서를 뒤집어 시각/읽기 순서를 다르게 만들지 않는다.
- 탭은 기본 링크·버튼·라벨 연결 input/select/textarea·radio/checkbox를 사용한다. 선택 그룹에는 이름과 대상 ID가 포함된 접근 가능한 라벨을 제공하고 목록 헤더는 선택 불가로 둔다. 양수 `tabIndex`로 이동 순서를 조정하지 않는다.
- 화면 이동 시 새 화면의 제목(`tabIndex=-1`)으로 포커스를 옮긴다. 목록 필터/선택만 바뀔 때는 조작 위치를 유지하고 선택/건수의 변화를 상태 영역에서 알린다.
- 입력 오류는 필드 라벨과 연결된 오류 문구·`aria-invalid`/`aria-describedby`를 함께 제공한다. 입력을 유지하며 제출 시 첫 오류 필드로 포커스를 옮기는 기준을 둔다. 오류/제한의 긴 설명을 색상만으로 구분하지 않는다.
- 처리/미연동·선택/건수 변경·주의 표본은 정중한 상태 알림(`role=status` 또는 `aria-live=polite`)으로, 입력 오류와 조회 실패는 `role=alert`로 연결한다. 처리 중 표시에는 `aria-busy`를 적용하되 예시 표본임을 함께 표시한다.
- 확인 취소/돌아가기의 복귀 대상은 호출 화면과 선택 ID를 보존한다. 인라인 확인이 사라질 때는 확인을 열었던 버튼으로 포커스를 복귀시키는 기준을 둔다. 실제 모달·포커스 가둠을 새로 추가하지 않는다.
- 포커스 테두리, 체크/라디오 모양, `선택됨`/`동결`/`확인 중` 등의 문자와 구역 제목을 함께 사용한다. 보라/초록/경고색만으로 상태를 판별하게 하지 않는다. 대비/확대/실제 터치 영역·기기별 수평 넘침은 제품 시험 전 판정 불가다.

## 11. 공통 화면 계약과 데이터 노출

최신 요청의 3단계다. [설계 §5의 권한별 DTO](library-management-design.md#5-접근표시보안-계약)·[§12의 SC01~08](library-management-design.md#structural-boundaries)을 화면별 props/이벤트로 좁힌다. 아래 타입/코드 경로는 프론트 껍데기용 계약이고 실제 서버 조회·권한·업무 명령이 구현됐다는 뜻이 아니다.

선택 File은 화면의 로컬 상태에만 둔다. 회원 입력 화면(`MemberScreens.screen`) 또는 선택 도서가 바뀌면 선택을 해제해 다른 대상에 보이지 않는 사진이 붙지 않도록 한다. 같은 입력 화면의 필드 오류와 독립 상태 표본을 열어 회원 입력 컴포넌트를 숨기는 동안에는 문자 입력/선택 파일을 유지한다. 다른 회원 화면으로 이동하거나 대상 도서가 바뀌면 사진을 다시 선택한다. 입력이 유지돼도 업로드된 파일/서버 임시 파일이 존재한다는 뜻은 아니다.

`RequestState.invalid`는 선언된 전달 상태다. 실제 회원 제출의 입력 오류는 `MemberScreens`의 로컬 오류 map·Field/FilePicker·Notice에서 표시하고 `onCommand`를 호출하지 않는다. 관리자 form은 기본 `required/pattern/type/min/step` 입력 제약을 사용하며, 회원과 같은 사용자 정의 오류 map/첫 오류 포커스를 구현했다고 집계하지 않는다. S09의 사유/확인과 A06의 범위 경고 확인은 비활성 버튼과 이유로 구별한다. 현재 previewGateway의 request/readResult는 전달된 초안/예시 참조를 not-connected로 종료한다. 선언된 invalid 반환형을 실제 서버/공통 검증 함수 구현으로 집계하지 않는다.

### 11.2 선택과 확인의 수명

- A01은 단일 대출 ID, A03은 단일 도서 ID 선택이다. 현재 A05 껍데기의 **대출만 복수 선택**이며, 동결 해제는 `freezeId`, 제재 해제는 `penaltyId`의 **각각 단일 선택**으로 종류별 ID/건수/상세를 분리한다. SC06 서버 계약의 복수 대상 목록을 모든 현재 선택 UI가 복수라고 해석하지 않는다. A06은 복수 Loan ID와 정리 범위를 보관한다. 제목/이름/행 번호를 식별자로 사용하지 않는다.
- 선택된 대상이 화면 필터에서 숨겨져도 선택을 보존하고 **현재 보이는 선택/숨겨진 선택/전체 선택 건수**를 고지한다. 상세는 선택 ID에 연결된 값만 표시한다. 새 필터의 첫 행을 이전 선택의 상세로 대체하지 않는다.
- 현재 예시 자료에서 대상 자체가 사라진 경우는 필터 밖 선택과 구별한다. A01은 이전 선택 ID가 없음을 고지하고, A06은 찾을 수 없는 이전 선택 건수를 따로 고지해 현재 확인 대상에서 제외한다. 관리자↔마스터 예시 모드를 바꾸면 AdminScreens의 mode key로 로컬 선택/초안을 초기화한다.
- A06 날짜 필터는 **반납 날짜** 기준이며 양 끝을 포함한다. 날짜 조건이 있을 때 반납 시각이 없는 활성 항목은 목록에서 제외하되 이전 선택은 유지한다. 선택·반납 날짜·사진만/DB 항목+사진 범위가 바뀌면 진행 중 확인을 취소한다. 예시 대상 표시/상태의 `dataSignature`가 바뀌어도 확인을 취소하며, 이는 로컬 합성 자료 비교이고 실연동 previewRef/revision/현재 권한 재검사는 SC06의 후속 서버 계약이다.
- 활성 기록의 DB 포함 정리는 **같은 A06 안의 확인 패널**에서 현재 선택·범위·활성 건수·대상 ID를 전달해 검토한다. S12 경로는 이 확인 표시의 **독립 표본**이며 실제 선택 수명을 대신하는 경로가 아니다. 사진만 정리는 활성 반납 판정/점유 해제/제재 변경을 뜻하지 않는다. 껍데기의 어느 확인도 실제 삭제를 수행하지 않는다.
- 이전 정리/부분 결과는 현재 선택 집합과 별개로 전달한다. DB 삭제 표본은 자원 ID·확인된 효과/남은 작업만 표시하고 이름·학번·증빙을 복제하지 않는다.

### 11.3 예시와 실제 결과의 구별

모든 껍데기 화면은 합성 예시 데이터/상태를 명시한다. M03/M06/S05/S10/S11 등 결과 화면은 별도의 **결과 예시 보기**로 열람하며 입력 제출의 응답처럼 표시하지 않는다. 실제 서버 연동 후에는 SC05/기존 CommandResult가 결과 의미를 결정하고 confirmed일 때만 실제 완료를 표시한다. 예시 계정/관리 화면 전환은 관리자 접근·권한을 부여하지 않는다. 운영 정책의 숫자·CF48~55 해석을 예시 값에서 확정하지 않으며 TV01~07은 미검증으로 유지한다.

### 13.3 유스케이스 기반 케이스와 변경 이유

요청의 5단계는 [TC-SHELL-01~30](library-management-skeleton-cases.md)에 연결했다. 모두 **미실행/판정 불가**이며, 사용자 요청의 대안인 기존 UC 기반 케이스 작성을 선택했다. Google Test 설치·새 테스트 실행 환경·새 업무 UC를 추가하지 않았다.

## 14. 화면 계약에 연결한 실제 프론트 검증 — 2026-10-05

사용자가 회원·관리자를 모두 포함해 검증을 재개했다. 기존 §11~13과 SC01~08·UC를 그대로 사용한 **브라우저 표본 TC-SHELL-01~30 전부 통과**, DTO/gateway 단위 8/8·외부 fetch 차단 단위 1/1·타입·린트·빌드 통과다. [케이스 §4](library-management-skeleton-cases.md#4-2026-10-05-실행-검증-재개)에 실제 환경/관찰·코드 연결·결함/재검증·한계를 기록했다. 제품 코드/Figma/DFD/업무 규칙을 이번 검증에서 변경하지 않았으므로 사용자 Figma 수정과 기존 계약은 유지한다.

- 회원: M01 검색/0건, M02 대상·필수 오류/사진 수명, M04/S07 이력, M05 반납 체크, M07 QR·연장 미연동, M08 주소/채널을 실제 조작했다. M03/M06/S05는 독립 결과 표본으로 유지됐다.
