# 도서관리 논의에서 도출한 저수준 검증 유틸 후보

2026-10-04 갱신. [도서관리 명세](library-management.md)와 [현행 요구사항 분석](library-management-analysis.md)의 입력·시간·설정·외부 데이터 처리에서 필요한 작은 함수 후보를 정리한다. 이름과 계약은 개발자 초안이며 구현된 API가 아니다. 도서·대출자·정책·쿠키를 모르는 범용 함수 수준을 유지하고, 최신 사용자 답변의 업무 규칙은 §5.1에서 호출부 책임으로 연결한다.

## 1. 범위와 선택 근거

각 함수는 주어진 값만 처리한다. 현재 시각·설정·파일/네트워크를 스스로 읽거나 데이터를 저장하지 않는다. 문자열 정리, 타입/형식 파싱, 단위 변환, 범위 비교, 키 기준 배열 처리까지 포함한다. 권수·연장 횟수·시간 제한의 값은 호출자가 전달한다.

| 방법 | 선택 이유·산출물 | 생략·현재 상태 |
| --- | --- | --- |
| P02·D03 | 기존 명세의 세부 설계 지원 문서. 작은 함수별 책임·입출력 표를 작성 | 새 기능/상태를 추가하지 않아 별도 FR·UC·클래스 계층·설계 그림 생략 |
| D04 | 화면/서버/스프레드시트 경계에서 같은 형식 검사를 쓰도록 성공/실패 타입과 파싱 계약 작성 | 검증 라이브러리·새 의존성 미선정. 실제 런타임 검사는 미구현 |
| D05 | 서버가 검증할 입력과 순수 함수의 한계를 명시 | 쿠키 해석·관리자/소유 확인은 별도 서버 책임. 여기서 접근 권한을 승인하지 않음 |
| T02 | 빈 값/다른 타입/허용 값/범위 밖 및 날짜·시각 경계를 예상 사례로 작성 | 테스트 계획이며 실행 미실시 |
| T03 | 포함/제외 선택과 중복 처리의 서로 다른 결과를 사례로 연결 | 대출 전체 결정표·상태 검증은 기능 설계에서 별도로 수행 |
| P07·M10 | 최신 사용자 답변과 이전 후보 계약의 적용 범위를 대조하고 업무 결정·기술 책임·미확정을 구분 | 고영향 미확정 규칙과 선행 TV는 분석 §12로 연결. 이 문서에서 임의 해소하거나 구현하지 않음 |

“후보”는 모두 지금 만들라는 뜻이 아니다. 실제 호출부가 생길 때 필요한 함수를 구현하며, 한 번 쓰는 간단한 표준 연산은 호출부에서 사용한다.

## 2. 작은 함수 후보와 계약

`Result<T>`는 아래 공통 성공/실패 표현을 뜻한다. 표의 형식·허용 범위는 재사용할 파서의 제안이다. 학번·이름·정책 값의 확정된 업무 규칙은 §5.1을 따르며, 그 규칙을 모든 문자열·정수 파서의 기본 의미로 바꾸지 않는다.

### 문자열·숫자·열거 값

| ID·함수 후보 | 입력 → 출력 | 정확한 처리·대표 사례 | 현재 필요 근거 |
| --- | --- | --- | --- |
| U01 `trimToNull` | 문자열 또는 null/undefined → 정리된 문자열 또는 null | 양끝 공백만 제거. `" 00123 " → "00123"`, 공백만 있거나 누락이면 null. 내부 공백·대소문자·문자 종류 보존. 문자열 아닌 값의 자동 변환 없음 | 선택 이메일·메모의 빈 값 정리; FR-LIBRARY-06·11 |
| U02 `parseNonBlankString` | unknown → Result<string> | 문자열만 받고 양끝 공백 제거 후 비어 있으면 거부. 숫자 `123`은 문자열로 바꾸지 않고 타입 오류. `" 00123 " → "00123"`, `"김  이름"`의 내부 공백 보존 | 제목·저자·분야·사유 등 필수 텍스트의 기초 검사. 회원 학번·이름의 최종 검사는 별도 업무 계약; FR-LIBRARY-06·08·17 |
| U03 `parseSafeInteger` | unknown, 선택 min/max → Result<number> | 안전한 정수 number 또는 양끝 공백 제거 후 `^[+-]?\d+$`와 일치하는 ASCII 정수 문자열만 허용. `" 2 " → 2`, `"002" → 2`. 빈 값/null/true/NaN/Infinity/소수/`"1.0"`/`"1e2"`는 거부. min/max는 포함 경계 | 권수·기간·연장 횟수·알림 오프셋 입력; FR-LIBRARY-09·19·23. 학번에는 사용하지 않음 |
| U04 `parseBooleanLiteral` | unknown → Result<boolean> | boolean 또는 양끝 공백을 제거한 `true/false` 문자열만 허용하고 문자열 대소문자는 무시. `"FALSE" → false`. `0/1`·빈 값·임의 문자열 거부. `Boolean("false")` 같은 진릿값 변환 금지 | 설정·스프레드시트의 명시적 체크 값; FR-LIBRARY-11·19·23 |
| U05 `parseEnum` | unknown, 문자열 허용 목록 → Result<허용 목록의 값> | 문자열의 정확한 일치로 허용 여부 판정. `"returned"`가 목록에 있으면 허용, `"RETURNED"`·누락·다른 타입은 거부. 별칭/기본값으로 자동 치환하지 않음 | 확인 상태·채널·삭제 범위 등 허용 값 검사; FR-LIBRARY-10·11·13 |

정규화는 입력 편의에 필요한 변환만 수행한다. 이메일 전체 소문자화, 학번 숫자 변환, 모든 문자열의 Unicode 정규화는 공통 기본값으로 추가하지 않는다. 도서관리 이름의 모든 공백 제거는 사용자 답변 Q16의 업무 규칙이므로 별도 이름 검증에서 수행하며 U01/U02의 내부 공백 보존 계약은 바꾸지 않는다.

### 날짜·시각·숫자 범위

`DateOnly`는 검증된 연/월/일 값이다. 날짜만 다루는 계산과 실제 시각/시간대 계산을 구분한다.

| ID·함수 후보 | 입력 → 출력 | 정확한 처리·대표 사례 | 현재 필요 근거 |
| --- | --- | --- | --- |
| U06 `parseDateOnly` | unknown → Result<DateOnly> | 정확한 `YYYY-MM-DD` 형식과 실제 달력 날짜 검사. 제안 표현 범위는 서기 1~9999년. `2028-02-29` 허용, `2026-02-29`/`2026-02-30`/`2026-2-3` 거부. 잘못된 날짜를 다음 달로 보정하지 않음 | 반납일·금지 날짜·정리 기준일; FR-LIBRARY-02·09·13 |
| U07 `parseTimeOfDay` | unknown → Result<number> | 정확한 `HH:mm`을 0~1439분으로 변환. `"23:59" → 1439`, `"00:00" → 0`. `24:00`/`12:60`/`9:5` 거부. 하루의 시각만 표현하며 종료일/시간대는 알지 못함 | 관리자 이용 시간 입력; FR-LIBRARY-15 |
| U08 `addCalendarDays` | DateOnly, 정수 일수 → Result<DateOnly> | 달력 날짜를 이동하며 입력을 변경하지 않음. `2026-10-04 + 13일 → 2026-10-17`, `2028-02-28 + 1일 → 2028-02-29`. 음수/0 허용, 소수·표현 범위 밖 결과는 거부. 시각의 24시간 덧셈과 구분 | 기간 상한·다음 날 날짜 계산 재사용; DEC-LIBRARY-37·45 |
| U09 `isInHalfOpenRange` | 유한 number 값, start/end → boolean | `start <= value < end`. `[0,2)`에서 0/1은 true, 2는 false. start=end는 빈 범위. NaN/Infinity는 false. 정상 경계 start<=end는 호출 전제 | 시간·숫자 비교의 포함/제외 실수 방지; BR-LIBRARY-06·08 |

U06·U07은 문자열 양끝 공백도 자동 허용하지 않는 엄격한 형식 파서다. 화면이나 외부 자료에서 공백을 제거하기로 한 경우 U01/U02를 명시적으로 먼저 적용한다. 시각 비교에 쓸 값은 호출자가 같은 단위와 시간대 기준으로 준비한다. U07만으로 자정을 넘는 운영 시간을 판정하지 않는다.

### 키 기준 배열 처리·파일 정보·이메일 형태

| ID·함수 후보 | 입력 → 출력 | 정확한 처리·대표 사례 | 현재 필요 근거 |
| --- | --- | --- | --- |
| U10 `findDuplicateKeys` | 배열, keyOf → 중복 키와 해당 인덱스 목록 | 키 `[A,B,A]`이면 `[{key:A,indexes:[0,2]}]`. 원본/순서 보존, 중복을 삭제하지 않음. 키는 string/number로 한정하며 `"1"`과 1은 다른 키 | 대출/도서 ID 중복 탐지; QR-LIBRARY-01 |
| U11 `uniqueBy` | 배열, keyOf → 배열 | 같은 키의 첫 항목을 남기고 원래 순서 보존. `[A,B,A] → [A,B]`. 입력 변경 없음. 중복 제거가 허용된 호출부에만 사용 | 같은 알림 시점의 중복 제거; DEC-LIBRARY-30. 손상 대출 행에는 사용 금지 |
| U12 `selectByKeys` | 배열, keyOf, include/exclude 키 집합 → 배열 | include=null이면 전체 후보, 빈 include이면 아무것도 선택하지 않음. exclude 우선. `[A,B,C]`, include=null/exclude={B}이면 `[A,C]`. 원본 순서 보존 | 포함/제외 필터의 기초 연산; DEC-LIBRARY-48. 필터 수명/권한/대출 적용은 알지 못함 |
| U13 `validateFileInfo` | size/type, minBytes/maxBytes/허용 MIME 목록 → Result<파일 정보> | 크기는 안전한 정수이고 두 경계를 포함해야 함. 허용 MIME과 정확한 일치 검사. 예시 범위 1~100이면 0/101 거부, 1/100 허용. MIME이 없거나 허용 목록 밖이면 실패. 입력 변경 없음 | 사진 업로드의 공통 검사; FR-LIBRARY-01. 업무 입력 상한은 Q14의 10MiB이며 호출자가 전달. 실제 내용 검사·변환 지원·보관은 별도 파일 처리 책임 |
| U14 `isEmailLike` | string → boolean | 공백이 없고 `@` 하나와 비어 있지 않은 양쪽 부분이 있는지만 검사하는 간단한 형태 검사. `a@b` true, `a@@b`/`a@`/공백 포함은 false. 주소 문법 전체·실제 수신/소유 확인을 보장하지 않음 | 이메일 입력의 명백한 오류 표시; FR-LIBRARY-11. 전체 문법 검증 필요 시 별도 계약 선택 |

U10은 오류 탐지, U11은 허용된 중복 제거다. 중복 활성 대출을 U11로 조용히 없애면 도서 상태가 잘못 풀릴 수 있으므로 원 자료 검증에는 U10을 쓴다. U13은 전달된 파일 정보만 검사하며 실제 파일 내용과 형식 일치는 서버의 파일 처리 경계에서 확인한다.

## 3. 실제 중복 사용이 생기면 추가할 후보

| ID·함수 후보 | 작은 계약 | 필요한 경우 |
| --- | --- | --- |
| O01 `intervalsOverlap` | 두 `[start,end)` 구간의 교집합이 비어 있지 않은지. `[1,3)`과 `[3,5)`는 false. 빈 구간은 겹치지 않음 | 동결 구간/운영 시간 구간의 겹침 검사가 여러 곳에 필요할 때 |
| O02 `mergeIntervals` | 유효한 구간들을 시작 순으로 정렬해 겹치거나 맞닿은 구간을 합치고 빈 구간은 제외. 원본 보존. `[1,3),[2,4),[4,5) → [1,5)` | 구간의 시간 합계에서 중복 집계를 피해야 할 때. 동결 업무 계산 자체를 확정하지 않음 |
| O03 `toDurationMs` | 유한 비음수 값과 명시적 단위를 밀리초로 변환하며 결과의 안전한 정수 표현을 검사. hour=3,600,000ms, duration-day=24시간. 범위 밖/알 수 없는 단위는 실패 | 정확한 시간 길이의 단위 변환을 여러 호출부에서 반복할 때. 달력 날짜 이동·D 알림 구간·동결 업무 시간 진행에는 사용하지 않음. H/D의 정책 의미를 이 함수로 확정하지 않음 |
| O04 `prefixIssuePaths` | 각 오류의 경로 배열 앞에 prefix를 붙인 새 오류 배열 반환. `["name"]`에 `["rows",2]`를 붙이면 `["rows",2,"name"]` | 배열/중첩 폼·외부 행의 검증 결과를 합칠 때. 오류 코드/메시지 변경 없음 |

이 함수들도 유효한 구간·단위를 호출 계약으로 받는다. 잘못된 내부 옵션/역전 구간은 개발 오류로 드러내며 정상 결과나 기본값으로 조용히 보정하지 않는다.

## 4. 오류 표현의 공통 타입 후보

오류 표현은 작은 공통 타입부터 두면 된다. 모든 오류 생성/배열 합치기를 별도 함수로 감쌀 필요는 없다.

```ts
type IssuePath = readonly (string | number)[];

type ValidationCode =
  | "invalid_type"
  | "required"
  | "invalid_integer"
  | "out_of_range"
  | "invalid_boolean"
  | "not_allowed"
  | "invalid_date"
  | "invalid_time"
  | "invalid_file_info";

type ValidationIssue = {
  code: ValidationCode;
  path: IssuePath;
};

type ValidationResult<T> =
  | { ok: true; value: T }
  | { ok: false; issues: readonly ValidationIssue[] };
```

코드 목록은 U01~U14의 예상 계약을 위한 초안이다. 표의 `Result<T>`는 `ValidationResult<T>`의 축약 표기다. 단일 값 파서는 필드 이름을 모르므로 기본 path는 빈 배열이며 호출부가 경로를 붙인다. 검증 결과의 code/path와 화면의 한국어 문구를 분리하고, 원본 학번·이메일·쿠키·파일 내용은 오류 객체에 기본으로 넣지 않는다. 예를 들어 호출부는 날짜 오류를 `{ code: "invalid_date", path: ["returnDate"] }`로 표현하고 표시 계층에서 “올바른 날짜를 입력해 주세요”로 바꾼다.

U01의 null과 U02의 required 오류는 서로 다르다. null을 허용하는 선택 필드인지 필수 필드인지는 호출부가 정한다. 성공 값을 확인한 다음에만 사용하며 입력 오류를 예외 발생이나 기본값 선택으로 숨기지 않는다. 저장/네트워크 실패와 업무 거부 사유는 이 입력 검증 타입과 별도 계약으로 둔다.

## 5. 기존 기본 기능을 그대로 사용할 부분

| 처리 | 사용할 기본 기능·구분 |
| --- | --- |
| 단순 문자 정리/비교 | `trim`, `includes`, 정규식 `test`. 필드 계약이나 타입 정제가 없으면 별도 래퍼 불필요 |
| 배열 조회/집계 | `filter`, `find`, `some`, `every`, `length`, `reduce` |
| 단순 키 집합 | `Set`, `Map`. 객체 배열의 중복 계약을 재사용할 때만 U10/U11 고려 |
| 필드 존재/배열/타입 확인 | `Object.hasOwn`, `Array.isArray`, `typeof`. 실행 대상의 지원 범위는 구현 시 확인 |
| 오류 문구 조회 | 오류 코드→문구 사전. 필요 전에는 범용 오류 프레임워크 추가하지 않음 |

`canBorrow`, `canRenew`, `calculatePenalty`, `resolveBorrowerRef`, `requireAdmin`은 업무/접근 함수이므로 이 목록에 포함하지 않는다. 23:59 기한·대출 당일 포함·현재 연장 정책도 호출부의 규칙이다. U08/U09를 조합할 수 있지만 해당 결정을 저수준 함수 안에 고정하지 않는다.

### 5.1 최신 업무 규칙과 순수 유틸의 경계

출처는 [질문형 확인 목록](library-management-confirmation-questions.md)의 사용자 답변과 현행 분석이다. 아래 업무 검증은 일반 파서와 구분하며, 아직 구현하지 않았다.

| 대상·근거 | 업무 호출부에서 적용할 규칙 | 공통 후보의 책임·한계 |
| --- | --- | --- |
| 학번·이름 / Q16 | 학번은 연도 4자리와 번호 5자리로 된 9자리 숫자 문자열. 이름은 양끝·내부 공백을 모두 제거하고 비어 있으면 거부하며 문자 종류는 제한하지 않음. 기록용 정보이며 인증·소유 키가 아님 | U01/U02의 양끝 정리·타입/빈 값 검사만으로 회원 입력 검사를 완료하지 않음. 학번은 숫자로 바꾸지 않고 선행 0을 보존. 별도 업무 검증에서 확정 형식을 적용 |
| 도서 필수값 / Q15 | 제목·저자·분야는 비어 있지 않은 문자열. 도서 등록 사진은 선택, 일반 대출 사진은 필수, 관리자 보충은 사진 없음+사유 허용(Q32) | U02는 기초 검사로만 재사용. 분야 열거 목록·사진 선택성을 범용 파서가 정하지 않음 |
| 정책 숫자 / Q11 | 최대 권수·회원 연장 횟수 상한만 -1=무제한, 0=금지. 신규·연장 기간은 양의 정수 일수. 제재 기간 0은 이후 새 제재 없음이며 기존 제재를 해제하지 않음 | U03은 전달된 정수 범위 검사만 수행. -1을 모든 숫자의 무제한 표현으로 바꾸지 않음. 제재 길이는 AS098의 정수 시간 가정으로 분석하며 이 자체 해석과 교정 위치는 분석 §12.2에 표시 |
| 이용 시간·회원 반납 / Q12·Q40·Q41 | [시작, 종료), 현재 업무 날짜의 평소 허용 시간과 특정 날짜 추가 시간의 합집합. 자정 후에는 다음 날짜 설정. 빈 구간은 차단하며 제한 없음은 별도 값. 회원 신규 대출·연장·반납은 현재 시간/날짜 규칙 검사, 관리자 관리 작업은 그 시간·금지 날짜 제한 면제 | U07/U09·O01/O02는 이미 같은 날짜·단위로 준비된 값의 형식/구간 처리만 수행. 날짜 정책 선택·자정 분리·회원/관리자 Guard는 업무 책임. 종료 경계의 다음날 00:00과 입력 24:00을 혼동하지 않음 |

| 프로필·관리자 계정 / Q33·Q37 | 대출과 별도 이용자 프로필에 학번/이름·확인 이메일·구독 설정을 관리하고 쿠키 접근과 구분. 마스터 계정·관리자 승격/박탈에는 서버 권한 검사 필요 | U14는 이메일 형태만 검사하며 소유 확인을 대신하지 않음. 프로필 저장·쿠키 해석·향후 계정 연결·마스터 준비·역할 부여/회수·세션 검사는 범용 검증 유틸 범위 밖 |

선행 기술 확인 TV01~07과 구현 전 직접 확인 대상은 [분석 §12](library-management-analysis.md#implementation-holds)에 모은다. 실제 소비자·계약·필수 결정이 준비된 작은 범위에서만 필요한 U/O 후보를 선택한다. 이 연결을 근거로 18개 후보를 일괄 구현하거나 새 검증 프레임워크·인증·저장소를 추가하지 않는다.

## 6. 검증 계획과 현재 상태

예상 결과는 위 계약에서 도출했다. 함수 구현과 테스트 실행은 아직 하지 않았다.

| 검증 후보 | 대상·입력 | 예상 결과 |
| --- | --- | --- |
| V01 문자열 보존 | U01/U02: `" 00123 "`, 내부 공백 이름, 빈 문자열, 숫자 입력 | 앞 0·내부 공백 유지. 선택 빈 값은 null, 필수 빈 값/다른 타입은 오류. U01 두 번 적용해도 같은 결과 |
| V02 정수 경계/암묵 변환 | U03: min=0/max=2에서 -1/0/1/2/3, 빈 값/true/소수/NaN/Infinity/안전 정수 범위 밖 | 0/1/2 허용, 나머지 적용군 거부. min=1에서는 0 거부 |
| V03 명시적 값 | U04/U05: `"FALSE"`, `"false"`, `"0"`, 정의된 상태/철자가 다른 상태 | false 문자열은 false, 숫자 표현 문자열은 거부. 열거 값은 정확한 일치만 허용 |
| V04 달력 형식/이동 | U06/U08: 윤일·없는 날짜·월/연도 경계·0/음수 이동 | 윤일 판정·월/연도 이동 정확, 없는 날짜 보정 없음, 원본 보존 |
| V05 시각/구간 경계 | U07/U09: 23:59/24:00, start 직전/start/end 직전/end, 빈 범위 | 올바른 시각만 변환. 시작 포함/끝 제외. 빈 범위는 false |
| V06 탐지와 제거 구분 | U10/U11: 중복 키·서로 다른 키·빈 배열·`"1"`/1 | 탐지는 중복 위치 반환·자료 유지, 제거는 첫 항목/순서 유지. 서로 다른 타입의 키는 구분 |
| V07 포함/제외 조합 | U12: 전체/빈 include/부분 include/포함과 제외에 같은 키/없는 키 | 전체는 후보 전부, 빈 include는 없음, exclude가 우선, 없는 키는 새 항목을 만들지 않음 |
| V08 파일·이메일 | U13/U14: 크기 최소/최대/밖·MIME 누락/허용 밖·단일/복수 @ | 선언한 정보 범위/목록과 형태 기준대로 판정. 실제 파일/주소 검증 완료로 확대하지 않음 |

문서 검토 기준은 입출력/빈 값/형식/경계/부작용이 드러나는지, 업무 규칙이 유틸에 숨어 있지 않은지, 함수마다 실제 재사용 근거가 있는지다. 현재 산출물은 함수 후보·검증 예상 사례·공통 오류 타입이며 코드·앱 동작·저장소/파일/알림 검증 통과를 뜻하지 않는다.

초기 문서 작성 당시의 검토 기록: 주 후보 14개·조건부 후보 4개·검증 사례 8개의 ID, 참조한 명세 ID와 문서 연결, 표 열/코드 블록/공백을 확인했다. 당시 기존 명세에는 이 문서 링크만 추가했고 기존 내용 보존을 확인했다. 함수 구현·단위 테스트·앱 실행은 수행하지 않았다.

이번 갱신의 문서 대조: Q11/12/14~17/18~20/28~46과 U01~14/O01~04의 책임을 비교했다. 일반 문자열 보존과 이름 업무 정규화, 일반 정수와 정책 -1, 정확한 기간 변환과 D/H·동결 의미, 파일 정보 검사와 실제 파일 정리를 구분하도록 수정했다. U/O/V의 기존 ID·후보 상태는 유지했다. 구현 전 보류·선행 TV 연결은 분석 §12를 따르며, 함수·앱 코드 수정 및 테스트·타입 검사·린트·빌드·브라우저 실행은 하지 않았다.
