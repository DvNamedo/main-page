Sheets 공동 batch는 같은 비공개 spreadsheet로 한정하며 실제 비밀은 별도 영역에 둔다. 불명 쓰기 복구는 고유 단계/세대 writeRef gate와 적용 marker·주소 안정성 후보로 구체화했다. 문서 대조만 수행했으며 TV01~07의 실제 실현성/테스트·타입 검사·린트·빌드·앱/모델 실행은 여전히 미실행이다.

> **2026-10-05 DFD 도면 교정:** [프로세스 모델](library-management-process-model.md)에 레벨0→1→각 처리의 레벨2→자료 정리4.4의 레벨3과 프로세스 표·CSPEC을 연결했다. [CDFD 보기](library-management-dfd.html)는 사용자 참고의 여섯 기호를 유지하며 선 겹침/잘림 지적에 따라 배치와 가로·세로 맞춤을 수정했다. 데이터/제어, 처리·외부/저장소 연결, 개별 처리 확대를 선택할 수 있고 모든 원문 흐름·ID를 유지한다. 문서 정적 대조와 도면 이미지 확인만 수행했다. 열린 file:// 탭은 브라우저 도구 제한으로 자동 새로고침하지 못했다. 업무 구현·제품 테스트 및 기존 보류는 유지한다.

> **DFD 계층 이름 후속 교정:** 처리 이름은 `P번호 · 이름`, 하위 번호는 `부모 번호.자식 순번`이다(예: P4→P4.4→P4.4.1). 도형에서 번호를 강조하고 도면 제목/경로에 부모→하위 범위와 조상을 표시한다. 상위 도면 및 선택 처리의 하위 도면으로 이동할 수 있다. 제어 처리 K4.4의 기존 참조 ID K44는 유지한다. 원문 흐름 불변·부모/자식 연결·표시 번호는 문서 정적 대조 및 도면 이미지로 확인했으며 제품 테스트 보류는 유지한다.

> **이전 후속 범위 — 시작 전 인계(역사):** 사용자는 SA 전체를 당장 검토하기 어려워 SA 변경 영향과 코드 복잡도 부담이 작은 작업을 원했다. 다음 작업을 **SD의 공통 처리·경계 상세화 → 도서관리 전체 화면의 표시·배치·접근성 설계 정비 → 화면별 데이터/입력/이벤트 계약 → 설계에 근거한 프론트 껍데기 구현**으로 정리했다. SD는 이 대화에서 SASD의 구조 설계/구조도 의미이며, 설계 문서의 SD01~06은 별도의 설계 결정 ID다. 이번 채팅에서는 요청에 따라 인계만 작성했고 이 후속 작업은 아직 시작하지 않았다. 당시 이어가기 요청은 §1의 이전 SD·UI·프론트 착수 인계 요청에 보존했다. §1 첫 코드 블록이 현재 재개 요청이다. 기존 ‘실제 앱 구현 보류’는 후속 프론트 껍데기 범위까지 자동 금지하는 의미로 재사용하지 않되, 실제 업무 처리·실연동·배포·CF48~55·제품 테스트 보류는 유지한다.

이 문서는 이 대화의 목적, 주요 논의 과정, 현행 결정, 작업 가정, 구현/검증 상태와 다음 작업을 요약한다. 상세 요구사항의 정본을 대체하지 않는다. 사용자 최신 답변 → 현행 분석/가정 대장 → 상세 UC → 과거 조사 기록 순으로 읽는다.

UI 초안은 그 의미를 제품 확정으로 고정하지 말고 별도 디자인 주석으로 표시하라. 내부 구조의 상세 설계는 OOD 단계에서 진행한다. 실제 앱 구현·테스트·타입 검사·린트·빌드·실서비스 작업은 아직 시작하지 마라. 현재 코드와 기존 변경을 보존하며 소프트웨어공학 지침에 맞는 범위·추적·검토 기록을 남겨라.

## 2. 최초 UI 인계 당시 사용자 지시와 중단 위치(역사)

1. 사용자는 기존 설명 중 “확정된 범위의 상세 설계”는 설계 단계에서 하면 된다고 정리했다.
2. UI는 아직 충분히 논의하지 않았으므로 **Figma로 초안을 만들어 달라**고 요청했다. UI 탐색과 다른 준비를 동시에 할 수 있다고 보았지만, 전체 OOD나 구현을 즉시 시작하라는 지시는 아니다.
3. 작업자는 기존 스타일과 요구사항을 읽고 Figma 연결을 확인했다. 화면 흐름을 준비하려 했으나, 사용자 최신 지시로 초안 제작을 중단했다.
4. **현재 채팅에서는 Figma 연결만 진행하고 전체 대화를 요약하여 다음 채팅으로 인계한다.**
5. UI/Figma 시안·가져오기 파일·프로토타입·새 업무 코드는 아직 작성하지 않았다. 다음 채팅에서 UI 작업을 시작한다.

### Figma의 확인된 상태

- 최초 검색 때 Figma 플러그인이 미설치였고 설치/연결 경로를 안내했다.
- 이후 다시 조회하여 `installed: true`를 확인했다.
- 설치 확인 직후에는 Figma 도구가 없었고, 사용자 완료 응답 이후 도구 목록에 Figma 도구가 나타났다. 초기 읽기 전용 `whoami` 2회는 `Unknown tool({"name":"figma.whoami"})` 오류였으나 **도구 활성화 이후 마지막 호출은 성공하여 인증된 계정 응답을 확인했다.** 이전 오류를 현재 연결 장애로 적용하지 않는다.
- **최신 사용자 응답: ‘설치·연결 완료’. 현재 확인 결과: 설치·계정 연결 및 읽기 전용 도구 호출 성공.** 계정 이메일·플랜 ID 등의 개인 정보는 인계 문서에 복사하지 않는다. Figma 파일 생성/수정/열람은 하지 않았으며 파일 URL도 없다.
- 설치/연결을 다시 요청하지 않고 다음 채팅에서 UI 초안을 이어간다. 이 연결 확인은 특정 디자인 파일의 쓰기 권한·생성·렌더링 검증을 뜻하지 않는다. 실제 작업에 필요한 파일/플랜 선택은 해당 Figma 스킬의 절차를 따른다.
- 초기에는 설치·연결 응답이 없었으나 인계 작성 중 완료 답변을 수신했다. 이 후속 응답이 앞선 ‘계정 연결 미확인’ 기록보다 우선한다. 다음 단계에서 설치 상태를 반복 조회하거나 같은 질문을 다시 보내지 않는다.
- 브라우저 우회, 토큰 추출, 임의 계정 생성, 권한 변경은 하지 않았다.

## 4. 제품 목적·범위·운영

- EDGE 동아리에 가입한 사람이 동방 책을 이용한다. 가입 검증/실명 인증 기능은 초기 범위에 없다.
- 실물 한 권이 하나의 도서 항목이다. 같은 제목의 수량 관리와 예약은 만들지 않는다. 대출 중인 실물은 신규 대출 불가다.
- 약 20권 정도의 규모로 조사돼 있으며 이용자는 학기당 5명 미만, 관리자는 1명 이상이다.
- 사실상 무료 운영. 동아리 계정과 서버컴이 있으며 기존 표를 사용한 경험은 거의 없어 이번 구축에서 의존하지 않아도 된다고 답했다.
- 고정 출시일은 없으며 준비되면 시작한다. 실제 사용 검토/테스트 환경은 마련할 수 있다.
- 기존 폼/활성 대출의 자동 이관은 초기 필수로 추가하지 않는다.
- 초기 제외: 회원 로그인·Discord 연동·NFC·OCR·예약·반납 사진·쿠키 분실 복구·학번/이메일 자동 병합·회원 반납 취소·공용 기기 대응·사이트 자체 삭제 복구.
- 관리자 업무는 도서/정책/사진 사후 검토/정정/대리 반납/보충 대출/예외/정리/시험·권한 관리다. 실물 확인과 회원 연락은 관리자의 현실 업무다.

## 5. 회원 식별·프로필·기록

- 초기 접근은 동일 브라우저 문맥의 식별 쿠키 하나. 이름/호스트/path를 일관되게 재사용하여 중복 쿠키 문제를 피한다.
- 쿠키와 독립된 안정된 `borrowerRef`를 두며 쿠키는 그 프로필의 접근 수단이다. 쿠키 자체에 학번/이메일 등을 신뢰할 원본으로 넣는 설계가 아니다.
- 학번·이름은 관리/실제 기록 확인용이며 소유/인증 키가 아니다. 쿠키를 잃어도 서버 기록은 남지만 회원이 접근을 복구하는 기능은 초기 제외다.
- 장기 미접속 2달의 앱 만료 예외는 사용자 답변이다. “달력 2개월, 없는 같은 일자는 말일”은 AS092의 해석이다. 접속 시 갱신하며 브라우저 자체 유실은 수용된 한계다.
- 매우 오래된 미반납을 임시 반납 취급하는 기능은 요청됐지만 기간·대상·실물 점유 효과는 CF48 보류다. 쿠키 만료와 자동 반납, 자료 보관은 같은 규칙이 아니다.
- 학번은 9자리 숫자 문자열 `YYYYNNNNN`. 앞 4자리 연도/뒤 5자리 번호, 숫자로 변환하지 않는다.
- 이름은 양끝과 내부 공백을 제거하고 빈 값 거부. 문자 종류는 제한하지 않으며 한국어 권장이다.
- 최근 학번/이름·이메일·구독 설정은 대출 항목과 별도 프로필에 보관한다. 대출 당시 입력/책 정보의 snapshot과 구별한다.
- 마지막 대출 DB 항목 삭제 또는 쿠키 유실이 프로필 삭제를 뜻하지 않는다. 프로필 보관 종료는 CF54 미확정이며 영구 보관 확정으로 기록하지 않는다.
- 향후 검증 계정이 같은 프로필을 참조하도록 연결 경계를 둔다. 현재 계정 이식/본인 확인/복구를 구현했다고 주장하지 않는다.

## 6. 대출·조회·반납·연장

### 정상 대출과 조회

- 관리자 등록 도서 중 선택, **책별 사진**, 학번·이름, 지금 대출하면서 반납 예정일 선택.
- 책 사진은 기록으로 보관하며 제목 자동 인식은 하지 않는다. 도서 등록용 사진은 선택, 정상 대출 증빙 사진은 필수다.
- 도서 등록 제목·저자·분야는 비어 있지 않은 문자열 필수. 도서/대출은 제목 대신 실물 ID로 연결한다.
- 공개 목록은 대출 가능한 책을 조회·제목/저자 검색·분야 필터로 찾는 목표다. 관리자 조회는 숨김·불가·대출 중·미연결 기록까지 포함한다.
- 내 대출과 DB에 남은 반납 이력은 같은 쿠키 소유 범위에서 조회한다. 회원에게 저장 증빙 사진/관리자 내부 메모를 공개하지 않는다.
- 신규 최대 기간은 대출 당일을 첫날로 센다. 예: 10월 4일, 최대 14일 → 10월 17일 기한. 샘플 값은 운영 확정값이 아니다.
- 최대 권수는 같은 `borrowerRef`의 미반납 합계. 동결/연체도 권수와 실물 점유에 포함한다.
- 권수 상한 -1은 무제한, 0은 신규 금지. 기존 미반납 권수가 상한보다 많아져도 강제 반납/기한 단축하지 않는다.
- 연체 미반납 또는 유효 반납 패널티가 있으면 신규 대출 차단. 외부 자료 불확실로 정상인지 알 수 없으면 영향 범위만 보류한다.
- 대출 완료에서 책·기한·내 대출 경로·쿠키 유실 한계/연체 안내를 제공한다. 사용자 관점의 결과와 서버의 실제 저장 확인을 일치시킨다.

### 반납

- 실물을 돌려놓은 뒤 사용자가 버튼으로 수동 표시. 반납 사진과 실제 과거 반납일 입력은 없다.
- 회원 반납은 현재 이용 시간 안이며 반납 금지일이 아닐 때만 허용한다. 이용 시간 밖에는 실제 반납을 가정할 수 없다는 최신 답변을 반영한다.
- 반납 완료 전 확인 단계는 현행 분석에 포함된다. 회원 반납 취소는 초기 제외이며 오입력/쿠키 유실은 관리자 정정·대리 반납으로 현실 업무 처리한다.
- 관리자 실물 확인 대리 반납은 소유 쿠키 없이 가능하며 이용 시간·반납 금지일 면제다. 연체 제재는 회원 반납과 같은 원칙이다.
- 최초 확정 서버 시각을 반납 처리 시각으로 쓴다. 중복 요청/재확인으로 반납 시각·제재 종료를 다시 계산하지 않는다.
- 반납 이후 새로운 알림 발송 중단. 이미 외부로 전달된 메시지 회수는 보장하지 않는다.

### 회원 연장

- 기존 반납 예정일에 **현재 별도 연장 기간**의 양의 정수 일수를 더한다. 고정 14일이나 요청일 기준 신규 최대 기간으로 계산하지 않는다.
- 대출별 현재 N회 상한과 성공 횟수 사용. -1 무제한/0 금지. 실패·중복 요청은 횟수 소비하지 않는다.
- 대상 대출이 이미 연체이면 회원 연장 불가. 동결로 과거 연체를 해소하거나 연체 허용 설정을 다시 추가하지 않는다.
- 비연체 동결 중에는 연장 가능하며 기간은 늘어나지만 날짜 진행은 계속 정지한다.
- 다른 책의 연체·반납 패널티·현재 권수 초과는 정상 기한 대상 책의 연장을 막지 않는다. 초기의 “대출 불가면 연장도 차단” 포괄 문장보다 Q05의 최신 답이 우선이다.
- 숨김 도서는 연장 불가. 신규 대출 불가만 설정한 책의 기존 연장은 허용한다.
- 현재 이용 시간·QR 확인·대상 상태·N 등 나머지 연장 조건 검사.
- 연장 결과가 반납 금지일이어도 허용하고 계산 기한 유지. 그날 회원 반납 불가를 안내한다.
- QR 확인은 10분, 그 안에서 재사용 가능. QR 교체/폐기 전 발행된 확인은 원 만료까지 유지한다. 관리자 권한 박탈과 같은 규칙으로 합치지 않는다.

## 7. 날짜·이용 시간·동결·제재

### 날짜/이용 시간과 정책 변경

- 업무 시간대는 KST. 기기 위치로 기준 날짜를 바꾸지 않는다.
- 기한 날짜 23:59 마지막 분 전체 포함. **다음 날 00:00이 배타적 종료/연체 경계**다.
- 요일별 복수 이용 시간 구간은 [시작, 종료), 합집합. 자정 후 새 날짜 설정 적용.
- 특정 날짜 추가 허용 구간은 평소 구간과 합친다. 빈 구간은 차단, 제한 없음은 별도 상태다.
- 원문의 25:59는 명시한 [00:00, 다음 날 00:00)과 충돌해 오타로 처리한 AS099다.
- 새 최대 대출 기간은 이후 신규 대출에 적용하며 기존 예정일은 유지한다. 현재 정책으로 권수/허용·금지 등을 판정하되 기존 제재 종료를 재계산하지 않는다.
- 정책값과 대응 변경 기록을 **둘 다 확인한 뒤** 새 정책 활성. 일부 저장/불확실이면 기존 유효 정책 유지·관리자 오류 표시.
- 설정 손상은 마지막 유효 정책, 없으면 검증된 초기 기본값 사용. 정상 판정 가능한 다른 업무는 계속하며 사이트 전체를 멈추지 않는다.
- AS013 초기 값은 분석/시험 표본 또는 기존 위임 기본안이며 실제 동방 운영 시간·휴무·운영 확정값으로 승격하지 않는다.

### 동결/관리자 확대

- 동결은 점검·오류 등을 위한 기한 진행 정지다. 이미 발생한 연체를 지우는 기능이나 보상 기능이 아니다.
- 날짜 기준. 사유별 독립 기록, 겹친 날짜 중복 계산 금지, 일부 해제 시 다른 유효 동결 유지.
- 즉시 시작·수동 해제만. 소급/예약/자동 종료는 초기 제외.
- 날짜 계산은 정지 중 지난 KST 자정 경계의 합집합이라는 AS003/083 모델. 같은 날 동결은 0일이며 중첩의 같은 자정은 1회다.
- 대상은 적용 당시 확인한 ID 목록으로 고정. 한 대출자/전체/일부 제외 등의 필터 가능. 이후 새 대출 자동 포함 없음.
- 전체 대출 선택은 쿠키 없는 관리자 보충 대출도 기본 포함하고 명시적으로 제외 가능. 학번으로 특정 프로필에 자동 귀속하지 않는다.
- 계산 기한이 20일이며 20일이 반납 금지이면 기한은 20일 유지, 20일에는 회원 반납 불가, 21일 00:00부터 연체. 19일로 앞당기거나 21일로 보상하지 않는다.
- 관리자 기간 확대는 기존 기한에 양의 정수 일수 추가. QR·이용 시간·회원 N과 독립, 회원 연장 횟수 증가 없음.
- 확대 전 발생 연체 보존, 새로 남은 기간에는 증가를 멈추고 소진 뒤 재개. 새 유예 중 차단/자정 누적/알림 결합은 CF49/51/55로 분리한다.
- 추가 후에도 기한이 과거면 새 유예 없이 진행하며 과거 누적분을 소급 차감하지 않는 AS104다. 최종 날짜 직접 입력은 선택 후보 AS105, 초기 필수 제외.

### 연체 반납 패널티

- 미반납 연체 동안 신규 대출 차단. 반납할 때 현재 설정의 정확한 기간으로 신규 대출 제한 발생.
- 제재 종료는 반납 확정 시각+기간. 날짜 끝으로 올림하지 않으며 대출 날짜 동결과 독립이다.
- 여러 건은 가장 늦은 종료를 적용. 기간을 합산하지 않는다.
- 기간 정책을 바꿔도 기존 종료 유지, 이후 새 제재만 새 설정 적용. 0은 이후 새 제재 꺼짐이며 기존 제재 해제 아님.
- 비음수 정수 시간·일수의 24h 변환은 AS098 분석 가정이다.
- Loan/사진 정리가 유효 제재를 지우지 않는다. 관리자가 별도 선택/사유로 해제 가능. 다른 제재나 연체 미반납까지 자동 해제하지 않는다.

## 8. 알림·사진·관리자·외부 편집

### 알림

- 이메일과 브라우저 사이트 알림을 각각 선택. 첫 대출/설정에서 묻고 수신하지 않아도 대출 가능하다.
- 프로필에 공통 적용. 주소 변경 후 알림은 새 주소를 사용하되 새 주소의 소유 확인 필요.
- 이메일 형태 검사는 소유 확인이 아니다. 서버가 주소와 프로필의 확인 상태를 검증하며 조작 쿠키의 true를 믿지 않는다.
- 설정에서 해제 가능. 해제를 주소 삭제와 강제로 묶지 않는다.
- 소유 확인 수신자가 쿠키를 잃어도 이메일 해제 링크로 해당 이메일 알림만 끄는 것은 AUTO-Q39의 구현 선택이다. 대출 복구/조회 권한으로 확대하지 않는다.
- 관리자 D-몇 일/H-몇 시간 전 규칙 여러 개 설정. 연체 발생과 연체 후 D+n도 추가 요청됐다.
- D-1 원문은 'D-1 : 48, 24) 시간 전'이며 정확히 24시간이라는 옛 가정과 다르다. 경계/첫 발송/구간 안 신규·재활성화는 AS095·CF50이다.
- H-n은 해당 시간 전. 날짜 동결과 정확한 남은 시간의 결합은 AS096·CF51이다.
- 늦어도 유효한 알림 발송, 다음 안내 시점이면 이전 지연 안내 생략. 고정 5분 폐기 규칙 없음.
- 동결 중 미발송 보류, 해제 시 현재 기한 재평가. 마지막 지연/연체 후 D+n 세부는 CF50/51/55다.
- 실패 원인별 자동 재시도·전체 실패 대응·외부 전달 보장/SLA는 아직 확정하지 않는다. 성공 확인/실패/불확실 구분과 중복 방지·진단 최소 책임은 유지한다.
- Chrome 등의 브라우저 알림 실제 지원·권한·무료 발송 경로·실행 주기는 기술 확인 전이다.

### 사진/사후 검토

- 일반 대출 후 관리자가 사진과 선택 책의 일치를 **사후 확인**한다. 대출 전 승인으로 바꾸지 않는다.
- 사진에서 촬영 시각/위치 등 있는 참고값을 추출해 관리자에게 제공한다. 누락은 받아들이며 진위/실물 확인 증거로 사용하거나 그것만으로 대출 거부하지 않는다.
- 10MiB 상한, 가능한 압축/변환 시도, 불가능하면 다른 형식 요청. 처리 파일만 보관하고 처리 전 원본은 버린다.
- 수상한 파일은 서버에서 거부/폐기. 선언 MIME 검사만으로 실제 파일 검증 완료라고 보지 않는다.
- 검토 결과는 미확인/일치/불일치/확인 불가 및 내부 메모. 불일치 자동 취소/회원 공개 메모 기능을 추가하지 않는다.
- 성공 사진 교체는 새 조합 재검토, 이전 파일/이미지 사본/이전 촬영 참고값 정리. 실패·결과 불확실이면 기존 유효 증빙 보존.

### 관리자와 예외

- 서버 시작 설정에서 마련하는 **영구 마스터 하나**가 도서 관리자 업무를 겸하고 다른 계정을 관리자 승격/박탈한다.
- 영구 계정은 영구 브라우저 세션을 뜻하지 않는다. 요청마다 현재 계정/역할 검사하며 박탈 후 이전 세션은 관리 권한을 유지하지 못한다.
- 마스터의 재시작 정체성 유지·일반 역할 변경으로 마스터 박탈 불가·마스터만 역할 관리는 AS101 최소 해석이다.
- 다른 계정 생성/기존·미래 회원 계정과의 연결은 AS100·CF52. 일반 회원 로그인을 지금 도입한 것으로 확대하지 않는다.
- 관리자 업무는 이용 시간·반납 금지 날짜와 무관하게 허용. 권한/입력/대상/점유·목표별 실물 확인 조건은 유지한다.
- 관리자 보충 대출은 확인된 과거 대출 시각·기한으로 쿠키 없는 기록을 만들 수 있다. 점유에는 포함하며 관리자만 관리한다.
- Q32 단일 'ㅇㅇ'은 사진 없음+사유, 최대 기간 초과·시간 밖 등록 모두 동의로 해석한 AUTO-Q32-ANSWER/AS090이다. 학번으로 알림·권수·제재를 추정 연결하지 않는다.
- 정정은 현재 값 교체. Loan 학번 정정이 프로필/다른 Loan 일괄 정정이나 소유 이전을 뜻하지 않는다.

### Sheet 직접 수정·부분 결과

- 대출 DB는 동아리 Google 스프레드시트와 Drive 사진을 연동하는 방향. 실제 계정/API 읽기·쓰기·삭제 권한은 아직 검증하지 않았다.
- 관리자 직접 수정은 다음 재조회에서 검증해 반영한다. 사전 '편집 중' 표시/수동 잠금 절차는 불필요하다는 Q28 답변이다.
- 드문 외부 편집 충돌은 사후 수동 정정. 이를 정상 사이트 요청의 점유/권수 동시성·중복 방지 책임 면제로 확대하지 않는다.
- 직접 행 삭제는 이전 활성 상태가 확인되면 최초 발견 시각 자동 반납 취급·새 제재 없음. 기존 유효 제재 유지.
- 이전 상태를 모르면 그 책 신규만 보류하고 관리자 실물 확인. 쿠키 전체 업무 보류/과거 삭제 시각 추정 없음.
- 사이트의 강제 DB 삭제와 직접 Sheet 행 삭제는 제재 처리 차이가 있으므로 합치지 않는다.
- 일괄 정리·동결·기간 확대·제재 해제는 항목별 부분 성공 허용. 성공 항목은 재실행으로 중복 효과를 만들지 않는다.
- 상태 변경은 최종 서버 판정 시각·당시 정책 사용. 이미 확정한 같은 시도는 원 시각·정책·결과 보존. 불확실은 확인 중으로 표시하고 관련 범위만 보류한다.

## 9. 자료 보관·삭제의 정확한 범위

- “두 학기 보관”은 잠정 운영 지침이다. 학기 말 관리자가 오래된 사진/대출 항목의 정리를 판단한다. 두 학기 자동 TTL이나 의무 보존 기능이 아니다.
- 관리자 항목 선택 또는 반납 처리 날짜 범위 도구로 **사진만 / DB 항목+사진**을 선택한다.
- 삭제 요청은 시스템에 실행을 요청하는 관리 기능이며 단순 담당자 메시지 전달로 임의 바꾸지 않는다.
- **사진만 삭제:** Loan/점유/제재/기한 유지. 추출 참고값·검토 결과·관리자 메모 유지, 사진 정리 사실 표시.
- **DB 항목 포함 삭제:** 해당 Loan의 사진/추출값/검토/메모를 정리하고 회원 이력에서 제거. 전체 원본 사본을 다른 곳에 숨겨 보관하지 않는다.
- **활성 항목 사이트 강제 삭제:** 경고/재확인 뒤 반납과 같은 제재 판정·점유 해제·알림 중단. 실물 반납 확인을 주장하지 않는다.
- 반납 확정 후 DB 정리가 실패하면 정리 완료까지 그 책 새 대출 보류. DB 삭제/사진 잔존은 남은 정리 결과를 표시하고 관리자 재처리 허용.
- 영구 삭제 우선. 기능·권한상 불가능함이 확인되면 Drive 휴지통. 결과 불확실은 불가능함의 확인이 아니며 실제 결과를 정확히 표시한다.
- 사진 교체 성공의 이전 자료 정리와 사진만 삭제의 참고값 유지는 다른 사건이다.
- 제재·프로필·필요한 처리 제어 상태는 독립 수명. 최소 참조/결과만 저장하며 숨은 개인정보 원본 아카이브로 확대하지 않는다.
- 콘솔/별도 수집 기술 로그는 삭제 기능 범위 밖. 학번·이름·사진·주소 등을 기술 로그의 기본 원본으로 복사하지 않는 것은 개발자의 보호 책임이다.
- 종료된 제재/정책/예외를 별도로 관리하는 영구 업무 아카이브·정리 화면은 초기 필수로 추가하지 않는다. 기존 정책 이력 조회/보관과 Q29의 관계는 CF53 보류다.

- 그 외 화면 구성/분할·레이블·배치·폼 단계·관리자 네비게이션은 **아직 사용자 검토를 받지 않았다**.

### 다음 초안의 권장 작업 범위 — 작업자 제안, 확정 UI 아님

- 회원: 책 목록/검색 → 대출 입력/사진/기한 → 처리/완료 → 내 대출 → 반납 확인/결과·연장·알림 설정.
- 관리자: 관리 목록/사진 검토 → 도서 관리 → 정책 → 기록 정정/대리 반납/선택 정리 → 동결/기간/제재 예외 → 마스터 권한 관리.
- 모바일 회원 흐름과 PC 관리자 흐름을 우선 검토하되 지원 기기/최종 화면 수는 아직 확정하지 않는다.
- 정상뿐 아니라 빈 목록·시간/권한 차단·사진 오류·처리 확인 중·일괄 부분 결과가 사용자에게 어떻게 보이는지 초안에 포함한다.
- CF48~55와 AS 값은 Figma의 별도 주석/검토 구역에 표시. 180일 등 분석 표본을 확정 운영 숫자처럼 화면에 박아 넣지 않는다.
- 쿠키 유실 안내를 로그인 화면으로 바꾸거나 사후 사진 검토를 승인 대기로 바꾸지 않는다.
- 초안의 버튼/상태/필드를 SR/UC/OP와 연결한다. UI 탐색에서 규칙 충돌이 드러나면 AS/분석을 교정하고 고영향 의미는 분리한다.
- 내부 모듈/DB 열/세션/외부 API/트랜잭션의 상세 책임은 후속 OOD다. Figma 화면 작성이 이 설계를 완료한 것으로 표시되지 않는다.
- P02(범위), P10(사용자 목표), P16(탐색 프로토타입), 필요한 설계/검토 방법을 선택하고 이유·산출물·미실행을 남긴다. 제품 테스트 지시를 자동 해제하지 않는다.

## 15. 다음 작업의 완료 기준과 금지되는 확대

1. Figma 설치·계정 연결과 마지막 whoami 성공 상태를 유지하고 초안 제작을 이어간다. 실제 디자인 파일/쓰기 범위의 확인은 계정 연결 확인과 구별하며 필요한 Figma 스킬을 먼저 읽는다.
2. 사용자 목표에 연결된 Figma 화면 초안과 검토 가능한 흐름을 만든다. 스타일/배치 선택은 디자인 가정으로 표시한다.
3. 정상·적용되는 차단·빈 결과·확인 중·부분 결과 표현을 준비한다. 화면 초안을 실행 제품/사용자 인수 통과로 보고하지 않는다.
4. 변경 파일/디자인 링크·요지·문서 대조/시각 검토 범위·남은 보류를 한국어로 짧게 보고한다.
5. 아직 전체 업무 구현·실계정 발급·DB/Drive 삭제·메일/Push·배포·테스트를 진행하지 않는다.
6. 단계별 승인이나 불필요한 질문을 자동 추가하지 않는다. 이번 UI 초안 요청을 전체 OOD/회원 로그인/정책 확정으로 확대하지 않는다.
