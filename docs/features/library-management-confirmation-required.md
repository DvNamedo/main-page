# 도서관리 — 사용자 직접 확인이 필요한 해석과 구현 보류 범위

2026-10-04 · 상태: **최초 CF47개 분리 근거 보존 / 기존 직접 질문 답변 수신·자체 해소 / 후속 분석의 고영향 CF48~55 분리**. 업무 코드 구현·기술 확인 결과를 뜻하지 않는다.

[분석 본문](library-management-analysis.md)·[가정 대장](library-management-assumptions.md)·[상세 UC](library-management-use-cases.md)·[원 결정/답변](library-management.md)을 대조했다. 가정 분석의 위임을 제품 정책 확정으로 확대하지 않는다. 최초 CF47개는 역사적 근거로 보존하고, 최신 구현 보류 CF48~55는 §0에 연결했다. 응답 원문은 질문형 목록, 현행 의미/교정 위치는 갱신한 분석과 AS 정본을 따른다.

후속 사용자 요청으로 [정적 진입 뼈대](library-management-skeleton.md)를 구현했다. 동급 홈 메뉴·준비 중 페이지·홈 복귀만 포함하며 이 문서의 CF를 확정하거나 보류를 해제하지 않았다. 코드/문서 리뷰만 수행했고 테스트·실행 검사는 사용자 요청으로 보류했다.

**최신 답변·현재 보류:** [질문형 목록](library-management-confirmation-questions.md)에 기존 직접44개 묶음을 답변 수신36개/재질문 제외8개로 연결했다. 실제 기술 제약 이후만 묻는 Q21/43/44는 유지한다. 현재 분석은 SR/UC/OP/사전/검증 계획을 새 답으로 교정했으며 그때 생긴 고영향 해석8개를 아래 §0에 모았다. §1~7의 ‘직접 확인 필요/응답 미수집’,AS61개 초기 분류 및 과거 통과 기록은 **역사적 최초 분리 근거**이며 최신 전체 보류로 적용하지 않는다. 문서 대조와 제품/기술 실행 검증은 구별한다.

## 0. 후속 분석에서 분리한 현재 구현 보류

정본은 [분석 §12](library-management-analysis.md#implementation-holds)와 [AS090~105 대장](library-management-assumptions.md)이다. 가정은 참으로 두고 분석을 진행했다. 아래는 직접 확인 전에 고정하면 실제 기한·권한·보관·외부 발송을 되돌리기 어려운 부분이며, 지금 사용자에게 응답을 요청하는 목록은 아니다.

<a id="cf48"></a>
### CF-LIBRARY-48. 임시 장기 미반납 자동 반납

- 분석 가정 AS093: 계산 기한 경계 후180달력일, active 전체 중 frozen/unknown 제외, 관측 시각 반납·새 패널티 없음·기존 제재/Loan 유지·점유 해제.
- 확인해야 할 의미: 기준일/기간/대상·동결·제재·실물 미반납인데 다시 빌릴 수 있게 하는 효과. ‘2달 미접속’이나 ‘두학기 정리’를 자동 반납 기간으로 합치지 않았다.
- 보류: SR064/OP31/TC030 전체 기능. 정상 수동/관리자 실물 확인 반납은 독립이다.

<a id="cf49"></a>
### CF-LIBRARY-49. 관리자 확대 이후의 연체 진행·회원 차단

- Q09의 과거 연체 보존/남은 기간 소진 뒤 증가 재개는 직접 답변이다. AS094/104는 누적을 KST 자정 단위로 세고, 추가 남은 기간에도 과거 연체로 신규 대출/회원 연장 차단을 유지한다.
- 확인해야 할 의미: 날짜 누적 단위와 추가 유예 중 차단 결과. 값/판정을 저장한 뒤 바꾸면 기존 연체·제재·후속 알림에 영향이 남는다.
- 보류: 연체 대출 관리자 확대의 누적/차단 결합·DD32/TC031. 비연체 정상 회원 연장과 기본 제재 계약은 독립이다.

<a id="cf50"></a>
### CF-LIBRARY-50. D 구간의 실제 발송 순간

- AS095: D-n은 남은24n시간 초과~24(n+1)시간 이하의 구간, 첫 유효 실행1회. 이미 구간 안에서 빌리거나 수신을 켜도1회.
- 확인해야 할 의미: 구간 경계/첫 발송·구간 안 시작/마지막 지연 상한. Q18의 범위 표기를 특정 발송 시각으로 보완한 것이며 외부 메시지 회수 불가다.
- 보류: D 규칙 발송/재활성화 기대값·TC009. 수신 선택/주소 확인/반납 후 발송 중단은 별개다.

<a id="cf51"></a>
### CF-LIBRARY-51. 날짜 동결과 시간 알림의 결합

- AS096: 날짜 기한은 정지 자정 수만큼만 이동, 미발송 안내 보류, 해제 시 현재 기한으로 재평가.
- 반례: 22:50~23:10 정지는 같은 날이라0일인데, 남은 시간을 정확히 정지시키면 H 안내가20분 이동한다. 현재 가정은 추가 분 이월이 없으므로 결과가 다르다.
- 보류: 동결/H/지연 결합·TC010. 사용자에게 날짜 동결과 정확 시간 동결을 서로 같은 뜻이라고 설명하지 않는다.

<a id="cf52"></a>
### CF-LIBRARY-52. 관리자 승격 대상 계정의 마련

- AS100: 마스터가 별도 관리자 접근 계정을 발급, 그 계정의 역할을 승격/박탈. 공개 회원 가입/쿠키 프로필 승격은 포함하지 않는다.
- 확인해야 할 의미: ‘다른 계정’이 이 별도 접근 계정인지, 기존/미래 회원 계정을 말하는지. 발급/계정 연결 범위를 고정하면 로그인·권한의 뼈대가 바뀐다.
- 보류: OP32 및 후보 계정 연결. 마스터의 현재 권한 관리/박탈 뒤 서버 거부는 직접 요구·개발자 책임이다.

<a id="cf53"></a>
### CF-LIBRARY-53. 정책 이력의 조회·보관 범위

- AS091: 종료 업무 아카이브/정리 기능은 추가하지 않고 유효 정책+대응 변경 확인 저장은 유지. 기존 FR22 정책 조회는 장기 범위 미정으로 둔다.
- 확인해야 할 의미: Q29의 별도 관리 불필요가 기존 정책 이력 화면/보관까지 제외하는지. Q25 동기 저장 요구를 로그만으로 대체하거나 모든 이력을 영구 DB 저장한다고 단정하지 않는다.
- 보류: 정책 이력 조회/종료 보관·정리. 정책+대응 확인 전 기존 유효 정책 활성 유지(Q25)는 그대로다.

<a id="cf54"></a>
### CF-LIBRARY-54. 독립 프로필의 보관 종료

- AS102: 쿠키 유실/마지막 Loan 삭제와 프로필 수명을 분리. 현재 자동 삭제 시점은 미정, 영구 보관 확정 아님.
- 확인해야 할 의미: 이메일·구독·최근 학번/이름을 언제까지 유지/정리할지. Loan 정리에 함께 지우면 Q37과 충돌한다.
- 보류: 프로필의 자동 정리/보관 기간 운영 확정. 별도 프로필 참조·접근 경계의 분석은 계속 가능하다.

<a id="cf55"></a>
### CF-LIBRARY-55. 연체 후 D+n의 진행 기준

- AS097: 최초 연체1회와 실제 누적 연체 진행n일 도달 안내1회, 동결/추가 남은 기간은 증가 보류.
- 확인해야 할 의미: 최초 연체 후 달력n일 경과인지 누적 진행n일인지, 동결 중 연체 안내도 보류할지. 기한 확대/동결 뒤 발송 날짜가 달라진다.
- 보류: 연체 후 안내·TC031. 최초 연체 안내 기능 요청 자체는 확인됐으며 실현성 TV는 별도다.

### 0.1 조건부 기술 확인과 수행 상태

TV01~07은 여전히 미실행이며 실제 제약이 요구를 바꾸는 경우에만 Q21/43/44의 구체 대안을 묻는다. 쿠키-프로필 연결·계정 인증·사진 삭제·알림은 문서 모델이고 실행된 기능이 아니다. 이번에는 최신 응답/AS/시간·권한·수명 반례를 문서로 대조했으며 새 업무 코드나 테스트/실계정 작업은 수행하지 않았다.

## 1. 최초 분리 결과와 사용 방법 — 역사적 근거

- **직접 확인 44개 묶음(U):** 해당 해석이 회원/관리자의 권리, 기한·제재, 자료 보관·삭제, 실제 외부 동작 또는 운영 장애 처리에 영향을 준다. 사용자 답변 없이 그 부분의 설계를 고정하거나 제품 동작으로 구현하지 않는다.
- **조건부 직접 확인 3개 묶음(C):** 먼저 개발자가 실제 지원/제약을 확인한다. 제약이 기존 요구를 바꾸는 경우에만 근거와 대안을 갖춰 사용자에게 결정받는다.
- **기존 가정 61개 전수 분류:** U41·C1·기존 확정(E)4·기술/설계(T)9·가역 선택(L)4·위임 범위 검토(R)2. AS 안의 **일부 해석만** U일 수 있다. U 표시는 그 행의 서버 검사/무결성 원칙까지 보류한다는 뜻이 아니다.
- 대장에 없던 누락도 따로 수록했다. EXIF/검토 메모·제어 자료·개인 설정·임시 파일 수명, 쿠키 없는 수신 해제, 시간 밖 반납·강제 삭제·일괄 시각 등이 해당한다. **새 누락에 임의 답을 채택하지 않았다.**
- 아래 확인 문장은 추후 직접 응답을 받기 위한 준비 문장이다. 이번 작업에서 질문 도구/실제 메시지 발송은 하지 않는다. 하위 선택이 여러 개이면 각각 답을 기록하며 일부만 답했다고 묶음 전체를 해소하지 않는다.

표의 **기반**은 해당 데이터/규칙/권한의 저장·인터페이스를 고정하기 전 확인할 항목, **기능**은 해당 기능의 동작을 고정하기 전 확인할 항목이다. 위험의 크기를 뜻하는 순위가 아니다. 화면/기술 실험이 가능하다는 것과 이 해석대로 영속 자료를 만들 수 있다는 것은 다르다.

### 1.1 보수적으로 포함한 기준

다음 중 하나라도 해당하고 기존 직접 답변/유효 위임으로 의미를 결정할 수 없으면 U에 넣었다. 발생 빈도가 작거나 수정 코드가 짧다는 이유로 제외하지 않았다.

1. 회원의 대출·연장·반납 허용/거부 또는 관리자 예외 권한이 달라진다.
2. 기한·반납 시각·연체 근거·제재 종료가 달라지고 이미 적용된 결과를 재판정해야 한다.
3. 자료를 처음부터 수집하지 않거나 삭제/별도 보관해 나중에 원래 값·관계를 복원하기 어렵다.
4. 사진·메일·Push·외부 직접 편집 등에서 앱 밖의 효과가 생겨 단순 코드 원복으로 되돌릴 수 없다.
5. 오류/부분 성공/불확실에서 정상 이용을 얼마나 넓고 오래 막는지, 누가 복구하는지가 달라진다.
6. 폼 필수성·입력 거부·개별 예외의 적용 범위처럼 비교적 작은 선택이라도 실제 운영 자료/기능에 의미 있는 영향을 준다.

보수 분리는 모든 기술 선택을 사용자에게 넘기는 절차가 아니다. **요구 의미 확인(U/C)**, **기술 가능성 확인(TV)**, **사용자가 이미 정한 제약의 구현 책임**, **바꿔도 과거 데이터/권리가 달라지지 않는 표현 선택**을 구분한다. 무결성·서버 권한 검사를 생략해도 되는지 또는 기술적으로 불가능한 일을 동의만으로 가능하게 만들 수 있는지는 묻지 않는다.

### 1.2 적용 방법과 실제 검토 범위

| 방법 | 이번 선택/실행 | 산출물·한계 |
| --- | --- | --- |
| P02/P06 | 문서의 권한·영속 자료·외부 효과/실패를 출처·반례로 재검토 | 변경 규모에 맞는 이 문서와 기존 4문서 상태 갱신. 전체 사이트 재분석 없음 |

### CF-LIBRARY-01 — 활성 대출 중 쿠키 만료 완화

- **곤란한 반례·되돌릴 범위:** 대출이 남은 채 365일 미접속하면 정상 설계한 앱 만료 때문에 조회·반납 연결을 잃는다. 브라우저의 임의 삭제 수용과 다르다. 나중에는 참조 수명·안내·기존 이용자 접근을 고쳐야 한다.
- **직접 확인할 내용:** 활성 대출 중에도 장기 미접속으로 앱이 정한 쿠키가 만료될 수 있는 요구 완화를 허용할지, 앱 만료를 계속 방지해야 할지 직접 결정한다.
- **확인 전 보류:** 만료·갱신 계약과 SR050/borrowerRef 수명 확정. 원 요구를 만족하는 대안 검증은 가능하다.

### CF-LIBRARY-40 — 동방 이용 시간 밖 회원 반납

- **직접 확인할 내용(기술 결과에 따라):** TV05에서 단절이 확인되면 기존 문맥을 계속 사용하고 이메일로 대체할지, 첫 대출 전에 지정 문맥으로 진입하도록 안내할지 직접 선택한다.
- **확인 전 보류:** 관찰된 단절을 감수하게 하는 강제 이동/진입 절차. 쿠키 없는 문맥을 학번/메일로 병합하지 않는 확정 제약은 유지한다.
- **영향 연결:** AS-LIBRARY-018; UC01/03/04; OP02/03/05; TC019; TV04/05. 상태: 기술 결과 전 / 요구 변경이 필요할 때 직접 확인.

### CF-LIBRARY-45 — Drive 파일 삭제의 실제 의미

- **분리 근거/유지할 확정:** 자료 정리와 사이트 자체 복구 기능의 초기 제외.
- **가정 또는 빠진 결정:** ‘지우기’가 휴지통 이동인지 영구 삭제인지, 외부 휴지통/복구 보장을 어떻게 안내할지는 미정이다.

- **직접 확인할 내용:** 실제 파일 정리는 휴지통 이동과 영구 삭제 중 무엇을 뜻하는지, 외부 복구 가능성은 기술 확인 후 어느 수준으로 안내할지 결정한다. 사이트 복구 기능을 새로 추가하는 질문은 아니다.
- **확인 전 보류:** 파괴적 파일 삭제 방식과 삭제 완료 의미 확정. TV02에서 권한/휴지통/실제 잔존·복구 한계를 확인한다.
- **영향 연결:** AS-LIBRARY-022·AS-LIBRARY-086; UC15; OP12; SR040/042/058; TC013/014; TV02. 상태: 직접 확인 필요.

### CF-LIBRARY-47 — 전체 동결과 전체 운영 중단의 구별

- **분리 근거/유지할 확정:** DEC61의 적용 당시 대상만·동결은 날짜 진행 정지.

- **곤란한 반례·되돌릴 범위:** 점검 목적으로 전체 동결을 눌렀는데 회원 신규 대출은 계속될 수 있다. 통합 조치를 원하면 정책 변경/동결의 부분 성공·복구와 운영 화면 계약이 달라진다.
- **직접 확인할 내용:** 기존 대출 동결과 신규 대출 차단을 별도 관리자 작업으로 운영해도 되는지, 함께 확인/적용할 운영 흐름이 필요한지 결정한다. 새 대출의 자동 동결은 확정 제외를 유지한다.
- **확인 전 보류:** 통합 운영 중단 workflow의 범위·부작용 고정. 동결 자체가 로그인 차단/신규 금지까지 의미한다고 확대하지 않는다.
- **영향 연결:** AS-LIBRARY-015·AS-LIBRARY-037·AS-LIBRARY-076; UC06/17; OP07/16; SR013/031/033; TC012/020. 상태: 직접 확인 필요.

### 3.2 이미 확인한 내용은 다시 선택 질문으로 올리지 않음

- 실물 한 권/활성 한 대출, 같은 쿠키 권수 상한, 쿠키 유실 복구 제외, 학번/이름 인증 아님, 관리자 사후 사진 확인.
- 기존 예정일+현재 별도 기간, 연체 회원 연장 금지, 시간 밖 신규/연장 차단, 날짜 동결·기존 연체 유지, 동결 중 비연체 연장 허용.
- 동결 계산 금지일의 기한 유지와 다음날00:00 연체, 적용 당시 대상만, 정확한 반납 후 제재·최댓값·기존 제재 종료 불변.
- 강제 삭제의 반납 동일 판정, 자료 정리 뒤 유효 제재 유지·관리자 별도 해제, Google 대출 DB·Drive·수동 선택 정리.
- 서버 권한 검사·현재 상태 재검증·같은 효과 중복 금지·거짓 성공 금지·손상 행을 빈 목록으로 바꾸지 않는 무결성 책임.

위 확정 요구를 만족할 수 없다는 기술 결과가 나오면 “다시 승인받았으므로 만족한다”로 처리하지 않는다. CF44에서 **요구 변경**을 검토하거나 요구를 만족하는 다른 기술 선택을 비교한다.

## 6. 직접 확인 결과를 반영하는 절차

1. CF ID와 하위 선택별 직접 답변·출처·날짜를 기록한다. 포괄적 “계속 진행”을 모든 수명/권한 완화의 동의로 해석하지 않는다.
2. 기존 DEC가 그대로인 부분과 새로 정할 의미를 구분한다. 답이 다른 CF/AS와 충돌하면 관련 조건을 함께 비교한다.
3. AS를 그대로 채택하면 답변 근거와 확인 범위를 기록한다. 바꾸면 [가정 대장의 교정 절차](library-management-assumptions.md#assumption-correction)대로 이전/새 의미와 영향 연결을 갱신한다. 새 누락은 실제 답을 받은 뒤 필요한 요구/가정 ID를 부여한다.
4. 관련 SR·사전·상태·OP·UC·AC/TC를 같은 의미로 맞춘다. U 해소와 TV 통과는 별도 증거다.
5. 다음 설계 작업에서는 필요한 CF 하위 항목이 해소됐고 TV 제약을 충족함을 확인한다. 이후 사용자의 새로운 명시 지시가 이 분류를 변경하면 그 범위만 갱신한다.
6. 아직 앱/실데이터가 없으므로 현재는 문서 정정 비용만 든다. 구현 후에는 저장 형식/사건·권한·외부 메시지·삭제 자료까지 영향/복구 한계를 다시 검토한다.
