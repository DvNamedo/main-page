# 도서관리 진입 뼈대 — 첫 구현 단위

2026-10-04. [기능 명세 양식](../templates/FEATURE_SPEC.md)을 이번 작은 범위에 적용한다. 전체 도서관리 기준은 [요구사항 분석](library-management-analysis.md), 미확정 동작의 보류 기준은 [직접 확인 목록](library-management-confirmation-required.md)이다. 이 기록은 목록 조회·대출 기능의 구현 명세를 대신하지 않는다.

> **최신 구현·검증 — 2026-10-05:** §1~5는 첫 진입점 구현, §6은 실행 전 껍데기 구현의 역사다. 후속 회원·관리자 검증은 §7과 [케이스 §4](library-management-skeleton-cases.md#4-2026-10-05-실행-검증-재개)가 정본이다. 브라우저 표본 30/30·단위 9/9, 타입·린트·빌드가 통과했다(기존 경고와 한계 별도). ‘입력 없음/정적 페이지뿐/전부 미실행’을 현재 상태로 보고하지 않는다. 실제 업무 처리는 미구현이다.

## 1. Planning: 목적·범위·결정

- 출처: 사용자의 최신 요청, “요구사항의 변경이 미치는 영향이 아주 미미한 사항에 대해서, 특히 뼈대부터 해서 개발을 시작”, “아직 테스트는 진행하지마”, “기존의 메인 페이지에서 About Us 와 Game Archive 와 같은 층위 메뉴의 다른 레이블”.
- 목표·이번 범위: 방문자가 홈의 동급 메뉴에서 도서관리 페이지로 들어가 서비스 준비 상태를 확인하고 홈으로 돌아온다. 메뉴·경로·정적 화면을 구현한다.
- 보류: 실제 도서 조회, 입력 폼, 쿠키 발급, 회원/관리자 권한, 대출·반납·연장·정책·사진·알림·Sheets/Drive 연동. CF47개 묶음의 확인 상태는 바꾸지 않는다.
- 시작 기준선: `Namedo/Book-Management`, HEAD `ade092b3e71b061da31cba24d912a7cd43c85369`. 기존 `AGENTS.md`와 `docs/`는 미추적 상태로 존재하며 보존한다. 이번 시작 시 앱 파일의 기존 변경은 없었다.
- 현재 환경 근거: `package.json`의 Next 14.2.3·React 18·TypeScript, App Router의 `/about`·`/archive`, 홈에서 사용하는 `BentoNav`. 새 의존성·설정 변경은 필요하지 않다.
- 변경 분류 P02: 새 페이지 진입 동작이므로 소규모 통합 기능 명세. 쓰기·권한·업무 상태 변경이 없는 범위라 이 파일 안의 축약 UC와 책임 표로 분석·설계를 기록한다.
- 검사 제약: 사용자 요청에 따라 자동/수동 테스트를 실행하지 않는다. 보수적으로 타입 검사·린트·빌드·개발 서버·브라우저 검사도 이번에는 실행하지 않는다. 문서/코드 읽기와 패치 검토만 수행한다.
- 착수 시 상태: Planning·OOA·OOD 기록 작성, 코드 미구현, 실행 검증 미실행. 구현 후 상태는 §5에서 별도로 갱신한다.

## 3. OOA: 축약 유스케이스와 시스템 경계

**UC-LIBRARY-ENTRY-01 — 도서관리 진입점 확인**

- 출처/목표: FR01~03. 방문자가 도서관리의 준비 상태를 확인한다.
- 주행위자/범위: 홈 방문자(회원·관리자 포함), 기존 EDGE 웹앱의 화면 이동. 회원/관리자 업무 권한을 부여하는 흐름은 아니다.
- 전제/Trigger: 기존 웹앱에 접근 가능; 홈 메뉴 선택 또는 `/library` 직접 접근.
- 성공 보장: 제목·준비 중 안내·홈 복귀 링크 제공. 최소 보장: 도서관리 업무 자료·식별·수신 설정을 변경하지 않음.
- 기본 흐름: 홈에 세 동급 메뉴 표시 → Library 선택 → 준비 상태 확인 → 홈 복귀 링크 선택 → 홈 이동.
- 대안: 직접 URL 접근 시 홈 메뉴 선택을 생략하고 같은 안내 표시.
- 예외 범위: 입력 폼·업무 조회·저장·외부 연동이 없어 해당 분기 없음. 앱 자체의 접근/라우팅 실패 처리는 기존 경계 유지.
- 인수 기준: TC-ENTRY-01~04. 쓰기·권한·업무 상태 전이가 없어 축약하며 기존 상세 도서 UC23개의 완료 상태를 변경하지 않는다.

**OP-LIBRARY-ENTRY-01**: 방문자의 경로 접근 → 정적 HTML 안내와 홈 링크. 업무 입력·상태 저장 없음. 페이지 표시가 도서 목록의 신선도나 대출 권한을 보장하지 않는다. 새 도메인 객체·데이터 사전·SSD/FSM/DFD는 이 정적 흐름에 필요한 추가 의미가 없어 생략한다.

## 6. SD·Figma·화면 계약 기반 프론트 껍데기

2026-10-05 최신 요청의 1~5단계. **프론트 껍데기 구현, 실행 검증 미완료.** 이전 분석과 UC를 다시 수집하지 않고 현행 기록/사용자 수정 Figma를 먼저 읽었다. 아래 설계 기준과 화면 계약을 구현 전에 정리했으며, 실제 코드와 미실행 케이스를 연결했다.

### 6.1 Planning·OOA·방법 선택

- 목적/행위자: 회원이 공개 책/본인 대출 표본을 탐색하고, 관리자가 선택 기록·도서·정책·예외·정리·접근·보충 초안을 검토한다. 실제 자료·권한·업무 상태를 바꾸는 책임은 범위 밖이다.
- 출처/요구: 최신 사용자 요청의 SD→UI→화면 계약→프론트→케이스 순서. 기존 UC01~25/OP/C/SC를 재사용하며 새 업무 규칙·목표·전체 SA 재분석을 추가하지 않는다.
- P02: 기존 기능 명세의 통합 기록에 프론트/실연동 구분·선택 수명·오인 방지 위험을 덧붙이는 범위다. 기존 분석/설계/UI 문서와 이 짧은 구현 기록을 산출물로 선택했다. 기존 Fully Dressed UC를 다시 작성하거나 업무 DFD를 변경할 이유가 없어 생략했다.
- P05/P06/P10, D02~05/D11/D12: 기존 책임·경계·계약·네이티브 React/Next/Tailwind 재사용 및 변경 영향 대조. 공통 폼·기록 표시가 실제 소비자를 가지므로 UI 함수만 공유하며 새 프레임워크/불필요한 저장소 추상 계층을 만들지 않았다.
- T01/T02/T03/T10/T11/T12: UC 기반 수동 케이스·입력/선택 전이·접근성 계획·별도 정적 읽기 리뷰·추적을 선택했다. Google Test는 사용자 요청의 대안 중 UC 기반 케이스로 대체했으며 C++/새 테스트 환경은 추가하지 않았다. 케이스는 30개, 전부 미실행이다.
- 완료 기준: 동일 대상 ID로 목록→상세/확인 이동, 입력·선택 표시, 공개/본인/관리 DTO 구분, 정상 0건/실패/처리 중/독립 결과 표본 구분, 미연동 요청에 실제 성공/자료 변경 없음, 문서·Figma·소스·케이스 추적. 실제 이벤트/접근성·타입/빌드 통과는 별도 미검증이다.
- 실패/제외: 실 인증·세션·QR·최종 대출/연장/제재 판정·Sheets/Drive·실 이미지·발송·실설정/실자료·배포는 제외한다. CF48~55 보류, TV01~07 미검증, U01~14/O01~04 후보 미구현 유지.

### 6.2 OOD·디자인 연결과 구현 선택

1. [설계 §12 SC01~08](library-management-design.md#structural-boundaries)에 입력 검사/권한 진입/조회·명령/결과·오류/선택/껍데기/외부·시간의 책임, 모듈 사이 SC-D01~10 데이터와 SC-C01~10 제어를 상세화했다. SC는 SD01~06 설계 결정과 별개다. SC02/04/08의 실제 서버 책임을 UI가 수행했다고 보고하지 않는다.
2. [UI §10](library-management-ui-draft.md#screen-display-refinement)의 Figma 현행 읽기를 기준으로 A03 단일 선택/서지와 편집 대상, A05 Loan/F/P 종류별 선택/상세를 보완했다. 원본 및 기존 탐색 복사에서 필요한 추가 표시만 수정하고 기존 A01/A06 헤더/행·동급 식별/선택·이전 결과 교정을 유지했다.
3. 기존 파일에 편집 가능한 회원 데스크톱 8종·관리 모바일 8종·긴/빈/진행/부분 표본 4종과 접근성 주석을 추가했다. 보드 [06 화면 표시·반응형·접근성](https://www.figma.com/design/Z8KgF0LpnRQaHduUmkn3iR?node-id=45-1043). 기존 디자인 시스템/색상/컴포넌트를 재사용했다. 원본/P/수정 파생의 A03 **추가한** 저자 라벨을 동일 제목 DTO에 맞춰 B02=저자 C·B03=저자 B로 교정했고 원본 제목·숨김/신규불가 값은 보존했다. B04~06은 동일 제목의 별도 대출 가능 실물 표본으로 공개·관리 목록에 함께 둔다. B-01과 B01 같은 Figma/코드 ID 표시 차이는 같은 canonical ID의 표기 차이다.
4. [UI §11~12](library-management-ui-draft.md#screen-contracts)에 28종의 DTO/props·입력/선택·이벤트·오류/처리 상태·노출·SC를 연결했다. Figma asset context에 구현용 이미지/SVG 자료가 없어 등록/증빙 사진은 자리표시와 파일 입력만 사용했다.
5. MemberScreens는 문자 입력 상태를 같은 컴포넌트 세션에 두며 M02→S03의 숨김 표시 동안 파일 입력도 보존한다. 다른 회원 화면/선택 도서 변경에는 파일을 해제한다. 관리자 내부 화면 컴포넌트는 화면을 떠나면 해당 초안이 해제되며, 결과/오류 표본을 여는 동안에는 이전 관리 화면을 숨겨 보존한다. 다른 상세 대상은 key로 새로 구성한다. 브라우저 새로고침/표시 역할 변경 뒤 저장·복구는 제공하지 않는다.
6. A06은 선택 집합과 필터를 분리하고 확인 snapshot에 ID·범위·날짜·표시/상태 signature를 고정한다. 선택/범위/날짜/자료 표본 변경으로 이전 확인을 취소한다. 실제 revision·previewRef·권한/경합 재검사는 서버 미연동이다. 실제 현재 선택의 S12 확인은 A06 안의 패널이며 메뉴의 S12는 읽기용 독립 표본이다.
7. 미연동 gateway의 읽기 함수와 명령 함수를 분리했다. 결과 조회도 readResult에서 미연동 종료하며 request로 재제출하지 않는다. 어떤 요청도 완료 표본으로 자동 이동하거나 fixture를 바꾸지 않는다. M03/M06/S05/S10/S11은 별도 표본 메뉴에서만 완료/부분 결과 문구를 검토한다.

복구는 새 LibraryClient 연결과 추가 프론트 파일의 가역 수정 범위이며 실제 자료를 되돌리는 작업이 없다. 이번 변경을 제거해야 할 때 기존 홈 메뉴/준비 안내와 이전 사용자 변경을 함께 지우지 않는다. 다음 요청에서 보류를 해제한 경우에만 해당 실행 검증을 수행하고 실제 결과를 기록한다.

## 7. 회원·관리자 프론트 실행 검증 — 2026-10-05

사용자가 관리자 검증과 회원 프론트 검증을 요청해 프론트 실행 범위만 재개했다. 기존 UC·SD·화면 계약을 기준으로 `tests/library/browser.test.cjs`에 TC-SHELL-01~30을 구현하고 Windows/Edge headless에서 **30/30 통과**했다. `preview-gateway.test.cjs`의 공개/본인 DTO·ID/상태·fixture 불변·결과조회/명령 분리 **8/8**, 실행 환경의 외부 fetch 차단기 단위 **1/1**도 통과했다. 기존 번들 Playwright와 Node test runner를 사용하며 앱 패키지/lockfile에 새 프레임워크를 추가하지 않았다.

타입 exit 0, 도서관리 범위 린트 무경고, 전체 린트 exit 0(기존 ReviewModal 경고 1건), 전체 Next 빌드 exit 0이다. 빌드에서 확인한 기존 About의 따옴표 오류 2건은 `about/page.tsx:65`의 `&quot;` 표기로만 교정했다. `.eslintrc.json`은 기존 Next 규칙, `.gitignore`의 `.library-test-output/`은 로그/캡처 제외를 위한 변경이다. 도서관리 제품 코드·BentoNav·Figma·DFD·업무 규칙은 이번 검증에서 바꾸지 않았다.

최초 성공 빌드의 Archive 정적 생성에서 기존 공개 Sheets 읽기가 발생했다. 실서비스 호출 제외를 빌드에 적용하지 못한 누락으로 기록하고, 이후 `block-external-fetch.cjs` preload를 적용해 재빌드했다(exit 0, 기존 fetch cache 사용). 실제 쓰기/실자료·실설정 변경·배포는 없다. 이를 실서비스 호출 0건이나 Archive 운영 연동 통과로 보고하지 않는다.

UC→SC01~08→28종 화면/DTO/이벤트→실제 테스트 연결, 환경·결함·재검증·캡처·재현 명령은 [케이스 §4](library-management-skeleton-cases.md#4-2026-10-05-실행-검증-재개)가 정본이다. 표본의 긴 값/대표 폭·필수 오류·키보드/포커스·명령 미전송을 실제 확인했으며 모든 화면의 줌·기기·보조기술·대비·운영 권한/경합·업무 성공을 검증한 것은 아니다. dev 서버/브라우저 context는 종료했다. **프론트 껍데기 구현 및 시험한 범위의 실행 검증 완료, 운영 연동 미완료**로 보고하며 CF48~55·TV01~07·공통 U/O 후보의 상태는 유지한다.
